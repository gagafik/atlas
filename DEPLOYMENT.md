# Размещение Атласа на сервере

Сервер ещё не выбран и облачная копия школы не создана. Репозиторий содержит
переносимую конфигурацию: один Python API с OR-Tools, собранный React-интерфейс,
SQLite и закрытые вложения в постоянном томе; Caddy обслуживает HTTPS.

GitHub хранит код и запускает проверки. GitHub Pages не исполняет Python и
не заменяет этот сервер. Supabase не является обязательной зависимостью.
Он может предоставить PostgreSQL/Auth/Storage, но переход потребует миграций
и переноса существующих прав, сессий и файлов. Генератору всё равно нужен
отдельный процесс Python. Подробности нагрузки — `PERFORMANCE.md`.

## До запуска

Нужен Linux-сервер с Docker Engine/Compose v2 и домен, направленный на его IP.
Для первого пилота разумная отправная точка — 4 vCPU, 8 ГБ RAM и SSD с запасом
под вложения/копии; это оценка для начала измерений, а не доказанная ёмкость
для всей школы. Проверка на целевом сервере обязательна до массового запуска.
Порты 80/443 должны быть доступны для HTTPS; порт 8000 наружу не публикуется.

```sh
git clone https://github.com/gagafik/atlas.git
cd atlas
cp .env.example .env
# Укажите домен и email администратора сертификатов в .env.
docker compose build
docker compose run --rm --no-deps app python -m tools.create_admin admin --name "School administrator"
docker compose up -d
docker compose ps
curl --fail https://YOUR_DOMAIN/api/ready
```

Пароль вводится интерактивно дважды. Он не передаётся аргументом команды,
не хранится в `.env` и не попадает в образ. Команда откажется менять существующие
аккаунты. `tools.serve` отказывается запускать API без активного администратора;
в серверном режиме потеря таблицы аккаунтов закрывает доступ, а не включает
локального администратора. Первый вход выполняется на вашем HTTPS-домене.

Для Caddy корректные DNS и доступные порты нужны для выдачи сертификата.
Проверяйте `docker compose logs --tail=100 web app`, не публикуя содержимое логов.
Внешняя публикация, домен и сертификат должны быть проверены после выбора сервера.

## Перенос текущей школы

Не включайте `data/` в Git и Docker-образ. На исходном компьютере выполните
`python -m tools.backup_school`, передайте готовую папку закрытым каналом и
проверьте `manifest.json`. Сохраните прежнюю базу отдельно. Остановите приложение
на целевом сервере перед восстановлением.

Из готовой копии в том `/app/data` должны попасть `timetable.db` и каталог
`timetable.files`, если он есть. Не переносите старые WAL/SHM. Если в переносимой
базе аккаунтов нет, создайте администратора **после** восстановления, затем
запустите сервис. Для владения файлами внутри контейнера используется UID/GID
10001; bind-mount каталоги требуют соответствующих прав. Именованный том
`atlas_data` на новом запуске получает права из образа.

Перед заменой БД сделайте резервную копию целевого тома; никакой скрипт проекта
не подменяет рабочие школьные данные автоматически. Сверьте число классов,
учеников, занятий, версии и доступы; выполните пробное скачивание вложения.

## Копии и обновления

```sh
docker compose exec app python -m tools.backup_school
docker compose cp app:/app/data/backups ./private-backups
```

Есть opt-in служба автоматических копий с проверкой и восстановлением в отдельную
папку, сроком хранения и состоянием для администратора. Включение профиля `backups`,
ограничения и порядок восстановления — в [BACKUPS.md](BACKUPS.md). Папка или отдельный
том на том же сервере не защищает от потери сервера: внешнее хранилище и серверная
приёмка ещё нужны. При больших объёмах замерьте длительность блокировки записи
во время согласованного снимка.

```sh
git pull --ff-only
docker compose build
docker compose up -d
docker compose ps
```

Перед обновлением проверьте CI выбранного коммита и наличие полной копии.
После — здоровье API, вход, права и неизменность школьных данных. Не используйте
`docker compose down -v`: этот флаг удаляет постоянные тома. Не увеличивайте
число API workers/реплик: текущие блокировки, очередь генератора и места
загрузок с очередью (`ATLAS_UPLOAD_SLOTS`, `ATLAS_UPLOAD_QUEUE`) рассчитаны на
один API-процесс. План миграции PostgreSQL и общего хранилища остаётся отдельным
этапом.

## Хранилище файлов

Файлы девяти разделов (домашние работы, сообщения, объяснительные, материалы уроков,
библиотека материалов, тесты, бюро находок, сайт школы, приём) лежат в закрытых
каталогах `<имя базы>.files/<раздел>` рядом с БД. У каждого раздела свой бюджет;
поверх них действуют общий предел и запас свободного места на диске. Значения по
умолчанию — стартовые потолки, а не выделенное место и не результат замера на
сервере школы: сверьте их с размером тома и измерьте загрузку
(`tools/benchmark_homework.py`) до приёма учеников.

| Переменная | По умолчанию | Что задаёт |
|---|---|---|
| `ATLAS_UPLOAD_HOMEWORK_MB` | 30720 | Домашние работы |
| `ATLAS_UPLOAD_MESSAGES_MB` | 8192 | Сообщения |
| `ATLAS_UPLOAD_ABSENCES_MB` | 2048 | Объяснительные |
| `ATLAS_UPLOAD_ASSIGNMENTS_MB` | 8192 | Материалы уроков |
| `ATLAS_UPLOAD_MATERIALS_MB` | 8192 | Библиотека материалов |
| `ATLAS_UPLOAD_QUIZZES_MB` | 4096 | Файлы тестов |
| `ATLAS_UPLOAD_LOST_FOUND_MB` | 1024 | Бюро находок |
| `ATLAS_UPLOAD_SCHOOL_SITE_MB` | 2048 | Сайт школы |
| `ATLAS_UPLOAD_ADMISSIONS_MB` | 2048 | Приём |
| `ATLAS_UPLOAD_TOTAL_MB` | 65536 | Один общий предел для всех девяти разделов вместе |
| `ATLAS_UPLOAD_RESERVE_MB` | 2048 | Свободное место на диске; ниже него загрузки получают 507 (`0` отключает проверку) |
| `ATLAS_UPLOAD_SLOTS` | 16 | Одновременные загрузки в процессе API (1–64) |
| `ATLAS_UPLOAD_QUEUE` | 64 | Сколько загрузок ждёт свободного места (0–1024) |
| `ATLAS_UPLOAD_WAIT_SECONDS` | 15 | Сколько ждёт загрузка в очереди (0–60) |

Размеры в МиБ, не меньше 10. Пустое или неверное значение означает значение по
умолчанию. Переменные читаются при старте: после изменения `.env` выполните
`docker compose up -d`. Учитывается занятое место с резервом 10 МиБ под каждую идущую
загрузку; исчерпанный бюджет раздела отвечает 413 с названием раздела и не мешает
остальным. Для расчёта: 1200 учеников по 0,5–1 МиБ на уменьшенное фото — порядка
30 000 фото в 30 ГиБ. Сумма бюджетов разделов по умолчанию — 65 ГиБ, общий предел
64 ГиБ намеренно ниже неё.

**Совместимость.** `ATLAS_UPLOAD_TOTAL_MB` сохраняет прежний смысл — один общий предел
на все хранилища. Изменился только предел по умолчанию: раньше `compose.yaml`
подставлял 2048, теперь пусто означает 65536. Если в вашем `.env` осталась строка
`ATLAS_UPLOAD_TOTAL_MB=2048`, на все файлы по-прежнему действует предел 2 ГиБ:
удалите строку (или оставьте пустое значение) либо задайте нужное число.

**Загрузки и повторы.** Когда все места заняты, запрос ждёт в очереди до
`ATLAS_UPLOAD_WAIT_SECONDS`, затем получает 429 с `Retry-After: 5`. То же относится к
лимиту незавершённых загрузок одного пользователя. Браузер повторяет такие загрузки
(до шести попыток с нарастающей паузой и случайным разбросом) и показывает «Сервер
занят, повторяем…»; другие ошибки и обрывы связи не повторяются, чтобы не создать
дубликат. Фото ученика длиннее 2560 px или тяжелее 3 МиБ браузер уменьшает до JPEG
перед отправкой. Число API-процессов не увеличивайте: места и очередь действуют в
пределах одного процесса.

**Хранение и очистка.** Файлы, на которые есть ссылки (история отправок, черновики,
сохранённые редакции, отправленные сообщения и заявления, опубликованные записи),
автоматически не удаляются. Брошенные загрузки очищаются порциями при новых
загрузках: незавершённые через 30 минут, готовые неиспользованные через сутки.
Квота сообщений на аккаунт — скользящее окно 30 дней: неотправленные файлы считаются
всегда, отправленные 30 дней после загрузки; сами отправленные файлы остаются.
Одинаковые материалы уроков (по SHA-256 и размеру) хранятся одним файлом и считаются
в квоте один раз; каждая запись сохраняет свои права доступа, а файл удаляется,
только когда на него не ссылается ни одна запись.

Освободить место вручную можно инструментом, который по умолчанию только печатает
отчёт (счётчики и байты по разделам, без имён и содержимого):

```sh
docker compose exec app python -m tools.backup_school        # сначала полная копия; проверьте manifest.json
docker compose exec app python -m tools.cleanup_files        # отчёт, ничего не удаляется
docker compose exec app python -m tools.cleanup_files --apply
```

С `--apply` удаляются только неиспользованные загрузки старше срока (`--days`, по
умолчанию 1 сутки) и неопознанные файлы `<32 hex>.bin` старше часа, на которые нет
записей. Файлы со ссылками, строки с отсутствующим файлом и файлы с чужими именами
не удаляются, а только учитываются в отчёте. Инструмент отказывается работать с базой
внутри Git-репозитория: на локальной установке с `data/` в проекте запускайте его на
сервере в контейнере или на копии вне проекта.

## Фоновые ведомости

Очередь подготовки итогов хранится в основной БД и восстанавливается при старте
API. Вычисления идут в дочернем процессе с тем же пользователем контейнера.
Используется тот же локальный вычислительный слот, что у генератора расписания.
Один API-процесс остаётся обязательным; отдельной распределённой службы нет.
Задание отменяется из раздела итоговых оценок; остановка API сохраняет очередь.
После аварии расчёт возобновляется с начала, не более трёх запусков.

Рядом с базой создаётся закрытый каталог `<имя базы>.grading` с промежуточными
SQLite-файлами. Они содержат ученические данные, исключены из Git/Docker-образа
и не нужны для восстановления: достаточно основной БД и готовых вложений.
Нужен запас диска под архив, общие факты и одну промежуточную ведомость; жёсткой
квоты пока нет. После обычного завершения/отмены собственный временный файл
удаляется. После аварийного завершения ОС файл может остаться: удалять его можно
только при остановленном API и всех его дочерних процессах, проверив точный путь
каталога. Автоматической очистки аварийных временных файлов пока нет.

## Источники

Администратору доступно окно **Состояние сервера**: скорость, ошибки, свободное
место, фоновые очереди и копии. Метрики хранятся в памяти одного процесса и
сбрасываются при перезапуске. Определения и границы — [SERVER_METRICS.md](SERVER_METRICS.md).
Внешнее оповещение оператора и долговременное наблюдение настраиваются отдельно.

Web Push по умолчанию выключен. Включение, сетевые требования, хранение ключа,
очередь и особенности восстановления описаны в [PUSH_NOTIFICATIONS.md](PUSH_NOTIFICATIONS.md).

Библиотека учебных материалов хранит файлы в `<имя базы>.files/materials`.
Они входят в бюджет раздела `ATLAS_UPLOAD_MATERIALS_MB`, общий предел
`ATLAS_UPLOAD_TOTAL_MB` (см. «Хранилище файлов») и в полную копию
`tools.backup_school`. При восстановлении переносите их вместе с базой;
не публикуйте этот каталог как статические файлы. Сохранённые версии и копии
могут ссылаться на один файл, поэтому ручное удаление файлов нарушит историю.
Подробнее: [MATERIALS.md](MATERIALS.md).
