# Категории работ ФО/СОР/СОЧ и доли в итоговой оценке

Каждая проверочная работа журнала имеет категорию. По умолчанию есть три:
**ФО** (формативное оценивание), **СОР** (суммативное за раздел) и **СОЧ**
(суммативное за четверть). Рекомендация итоговой оценки считается не по
среднему всех работ, а по долям категорий. Это аналог категорий и способов
расчёта оценок в EduPage и ответ на запрос школы «ФО, СОР и СОЧ с весами».

## Кто что может

| Кто | Возможности |
|---|---|
| Администратор | Называет и настраивает категории, доли, метод расчёта и правила для предметов и классов (панель «Итоговые оценки» → «Категории работ и доли в итоге»). Видит список предметов и классов для правил. |
| Учитель | Выбирает категорию и вес при создании работы, видит доли школы, но не меняет их. |
| Родитель и ученик | Видят название и цвет категории у работ, в ленте оценок и в отчёте. Доли, правила и списки предметов им не передаются. |
| Сотрудник без доступа к журналу | Каталог категорий не читает (403). |

## Категории

- Идентификатор (`fo`, `sor`, `soch`) не меняется. Название (до 12 знаков),
  описание, цвет и признак «Действует» можно менять. Переименование `fo`
  меняет только подпись: прежние работы следуют новому названию.
- **Категорию нельзя удалить, её можно отключить.** Отключённая категория не
  выбирается для новых работ, но работа, уже имеющая её, сохраняет метку и
  может быть пересохранена. Категорию по умолчанию отключить нельзя.
- Категория по умолчанию (изначально `fo`) подставляется, если работа
  сохранена без категории (старый клиент, домашняя работа, тест без категории).
- **Связь с календарём контрольных.** Типы календаря «СОР» и «СОЧ» привязаны к
  категориям (`summative_unit` → СОР, `summative_term` → СОЧ); тип «другое»
  и непривязанные типы дают категорию по умолчанию. Один тип календаря может
  быть связан только с одной действующей категорией.
- Всего до 20 категорий. Все изменения версионируются, записываются в историю
  (`assessment_category_history`) и журнал действий (`journal.categories`).

## Как считается итог

Для ученика по предмету за период для каждой категории считается процент,
затем берётся взвешенная по долям сумма:

```
итог = Σ(доля · процент категории) / Σ(доли категорий, в которых есть оценки)
```

Метод расчёта процента категории задаётся правилом:

| Метод | Формула | Пример: ФО 9/10 (вес 1) и 10/20 (вес 1) | Тот же пример с весами 1 и 2 |
|---|---|---|---|
| `average` — «среднее процентов с весом» (в EduPage «каждая отдельно») | Σ(балл/максимум·100·вес) / Σвес | (90 + 50) / 2 = 70 % | (90 + 100) / 3 = 63,33 % |
| `points` — «сумма баллов» | Σ(балл·вес) / Σ(максимум·вес) · 100 | 19 / 30 = 63,33 % | 29 / 50 = 58 % |

Все вычисления идут точными дробями (`Fraction`); округление до шкалы
выполняется один раз в `final_grades.recommendation`, пороги сравниваются
точно. Пример по умолчанию: ФО 80 %, СОР 70 %, СОЧ 60 % при долях 25/25/50 дают
(25·80 + 25·70 + 50·60) / 100 = 67,5 %.

**Доли по умолчанию 25/25/50 — предположение** (так делится четверть по
правилам Казахстана). Школа должна подтвердить свои доли в настройках, как и
значения по умолчанию календаря контрольных. Доля — число от 0 до 100 не более
чем с двумя знаками после запятой (33,33 + 33,33 + 33,34); сервер хранит
сотые, и редактор не отправляет доли с большим числом знаков. Если сохранение
не удалось (сеть, права, ошибка проверки), введённые правки в редакторе
остаются; страница загружается заново только после 409 (настройки уже изменил
другой администратор).

### Категория без оценок

Режим `missing` выбирается в правиле:

- `renormalize` (по умолчанию) — категория без оценок исключается, доли
  остальных пересчитываются. Четверть без СОЧ: ФО 25 + СОР 25 → 50/50.
  Отсутствующая категория никогда не считается нулём;
- `block` — рекомендации нет, пока оценки не появятся во всех категориях с
  долей. Итог при этом можно поставить вручную с обязательным пояснением.

Не входят в расчёт: текстовые оценки (A*, зачёт), пустые оценки и работы с
весом 0. Категория с оценками, но без доли (0 %), в расчёт не входит и
показывается как «без доли». Минимум работ в шкале (`minCount`) считает только
оценки категорий, вошедших в расчёт.

### Вес работы

В редакторе журнала вес выбирается из набора 0x, 0,25x, 0,5x, 1x, 2x, 3x или
«Свой» (от 0 до 100). **0x в Атласе — работа исключена из расчёта**, в отличие
от EduPage, где 0x даёт дополнительные баллы без максимума.

### Правила для предметов и классов

Администратор может добавить до 50 правил: у правила есть название, списки
предметов и классов (пусто — любые), доли, метод и режим пустых категорий.
Действует **первое подходящее правило сверху**; если ни одно не подошло, берутся
доли по умолчанию. Правила по номеру параллели не поддерживаются: у класса нет
поля «параллель», нужно перечислить классы. Правило хранит идентификаторы
предметов и классов; исчезнувший позже предмет просто перестаёт совпадать.

## Ведомость и итоговые оценки

- Доли и правило **закрепляются при подготовке ведомости**: каждая строка
  хранит суммы по категориям и снимок правила (названия, цвета, доли, метод).
  Изменение настроек после этого не меняет подготовленную ведомость; следующее
  закрытие и подготовка используют новые настройки. Если администратор изменит
  доли между закрытием периода и подготовкой, ведомость получит новые доли.
- Ведомости, подготовленные до Ф2, и уже опубликованные итоги не пересчитываются:
  рекомендация старой строки считается прежним средним всех работ.
- Общий кэш фактов (`grading_facts`) обновляется один раз: факты со старым
  форматом (`grading_projected.format = 1`) пересоздаются из архива закрытия.
  Идентификаторы фактов сохраняются, поэтому курсоры просмотра работ действуют.
- Панель итоговых оценок показывает вклад категорий: «ФО 25 % — 80 %; СОР
  25 % — 70 %; СОЧ 50 % — нет оценок», метод, правило и список пустых
  категорий. В списке работ архива у каждой работы есть метка категории.

## Миграция журнала

При первом чтении журнала после обновления выполняется разовое заполнение
(метка `assessment_categories` = 1 в `journal_projection_versions`, под общим
замком записи, в одной транзакции). Всем работам в черновике и опубликованной
копии без категории записывается `fo`. Версии журнала, история
(`journal_history`), архив закрытых периодов и события оценок **не
перезаписываются**: их работы без категории читаются как ФО. Повторный запуск
ничего не меняет; при сбое транзакция откатывается без метки, и следующее
чтение повторяет попытку.

Перед обновлением боевого сервера сделайте копию `python -m tools.backup_school`
(см. `DEPLOYMENT.md`) и проверьте время заполнения на копии: оно перезаписывает
каждую запись журнала, в которой есть работы.

## Журнал: категория и связь с календарём

- Работа журнала имеет `category` и необязательный `bookingId` (бронь
  календаря контрольных). При сохранении пустая категория заменяется категорией
  по умолчанию или (если выбрана бронь) категорией, привязанной к типу брони;
  неизвестная категория даёт 422, отключённая — 422 (кроме работы, которая уже
  имела её).
- Редактор показывает «По календарю контрольных» для работ на этом уроке и
  кнопку «Добавить работу из календаря»: новая работа получает тему брони и
  категорию типа. Учитель может выбрать другую категорию.
- Связь записывается в документ брони (`journal.assessmentId`) в той же
  транзакции, что и ревизия журнала, и в историю календаря
  (`journal_linked`, `journal_unlinked`). Версия брони при этом не растёт: связь
  — служебные данные, и редакторы календаря не получают 409.
- Удаление работы из журнала снимает связь (если бронь всё ещё ссылается на
  эту работу). **Перенос брони на другой урок снимает связь**; работа журнала
  при этом хранит категорию и `bookingId`, но в редакторе не показывается
  связанной. Отмена брони связь и категорию не меняет, урок остаётся
  сохраняемым. Смена типа брони категорию работы журнала автоматически не
  меняет.
- Новая связь проверяется при установке: бронь должна быть действующей и
  относиться к этому же уроку (иначе 422), одну бронь нельзя привязать к двум
  работам (422 или 409). Закрытый период блокирует и связь, как и любое
  изменение журнала. Семья `bookingId` не получает.

## Домашние работы и тесты

- Новая работа при переносе оценки за домашнее задание получает категорию по
  умолчанию школы (изначально ФО); форма проверки позволяет выбрать другую
  действующую категорию. Связь с календарём здесь не задаётся (422), её делает
  учитель в журнале урока.
- Конструктор теста содержит поле «Категория в журнале» (`journalCategory`):
  результат теста переносится в эту категорию. Пусто — категория по умолчанию.
  Если категория теста позже отключена, перенос использует категорию школы по
  умолчанию. Оценка существующей работы категорию не меняет.

## Что видит семья

- Отчёт журнала и лента оценок показывают метку категории у каждой работы.
  Изменение категории опубликованной работы создаёт событие «изменена».
- Итоги отчёта за период: прежний `percentage` (средний процент всех работ)
  не изменился; добавлены `categories` (процент каждой категории),
  `sharePercentage` (процент по долям школы) и `rule` (название правила).
- В CSV журнала после «Вес» есть столбец «Категория».

## Интерфейсы

- `GET /api/journal/categories` — каталог для всех, кто читает журнал; политика
  и правила — сотрудникам (учитель, администратор); администратору также
  `canEdit`, `subjects`, `classes`.
- `PUT /api/journal/categories` — только администратор; тело: `version`,
  `reason`, `categories`, `defaultCategory`, `policy`, `rules`. Устаревшая версия
  — 409, удаление категории — 422, сумма долей не 100 — 422, правило для
  неизвестного предмета или класса — 422 (уже сохранённые идентификаторы
  допускаются).
- `GET /api/journal/entry` — дополнительно `bookings` (только сотрудники).
- `PUT /api/journal/entry` — заполняет и проверяет категории, ведёт связь.
- `GET /api/journal/homework/{урок}/grading` и аналог для тестов —
  `categories`, `defaultCategory`.
- `GET /api/journal/report` — `categories`, `sharePercentage`, `rule` в итогах.
- `GET /api/journal/grades/feed` — `category` и `previous.category`.
- `GET /api/journal/course-table/courses`, `GET /api/journal/course-table` и
  `POST /api/journal/course-table/save` — таблица курса: категории работ и
  проценты категорий, итог по долям считаются теми же функциями, что в отчёте
  семьи; публикация из таблицы переносит работы вместе с их категориями
  ([COURSE_TABLE.md](COURSE_TABLE.md)).
- `GET /api/assessment-calendar/bookings` (сотрудники) — `journalAssessmentId`.
- `GET /api/final-grades/rows/{строка}/evidence` — `recommendations` с вкладом
  категорий и `category` у каждой работы.

## Ограничения

- Нет стандартного отклонения и статистики курса. Таблица курса «ученики ×
  работы» есть ([COURSE_TABLE.md](COURSE_TABLE.md)), но показывает только
  проценты категорий и итог по долям.
- На одну работу приходится одна оценка ученика. Способы EduPage «лучшая»,
  «последняя», «сумма со средним» и «сумма с добавлением максимума» не
  реализованы; есть «среднее с весом» и «сумма баллов».
- Вес 0 означает «не входит в расчёт», а не «дополнительные баллы».
- Работа входит ровно в одну категорию.
- Итог по годовой оценке из итогов периодов и веса экзаменов не реализованы:
  итоговые оценки по-прежнему считаются по одному закрытому периоду.
- Нет правил «по параллели» (у класса нет номера параллели).
- Нет автоматической смены категории работы при смене типа брони и нет экрана
  истории настроек категорий (история хранится и записывается в аудит).
- 25/25/50 и режим `renormalize` — предположения, которые школе нужно
  подтвердить.
