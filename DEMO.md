# Демо Атласа на GitHub Pages

Адрес: https://gagafik.github.io/atlas/ (роли: `?as=admin`, `?as=teacher`,
`?as=parent`, `?as=student`).

Это статический показ для презентации: вымышленная «Школа Пример», время
остановлено на понедельнике **2 ноября 2026, 11:30** (Asia/Qyzylorda), ничего
не сохраняется. Сервера нет: GitHub Pages отдаёт файлы, а браузер отвечает на
запросы интерфейса к `/api/…` из заранее снятого снимка
(`tools/demo/snapshot/<роль>.json`). Любая запись (сохранить, опубликовать,
записаться, отправить, выйти) получает ответ «Это демо: изменения не
сохраняются».

Демо не доказывает готовность функций: оно показывает снимок экранов на
вымышленных данных. Правила проекта — [AGENTS.md](AGENTS.md).

## Роли для показа

| Роль | Ссылка | Что показать |
| --- | --- | --- |
| Администратор | `?as=admin` | расписание, контроль журналов, посещаемость, итоговые оценки, нагрузка, замены, сообщения, формы |
| Учитель | `?as=teacher` | день, урок с отметками, таблица курса, очередь домашних заданий, результаты теста, консультации |
| Родитель | `?as=parent` | лента, оценки, посещаемость, домашние задания, расписание, запись на консультацию (показана, не сохраняется), сообщения |
| Ученик | `?as=student` | расписание, домашние задания, оценки, тест |

Верхняя полоса демо переключает роль без входа. Выбор запоминается на вкладке.
Кнопки, которые на статической странице работать не могут (установка
приложения, приглашения, пароль, резервные коды, ссылки публикации, табло,
состояние сервера), в демо скрыты. Показываемый ученик и его родитель — одна
семья из 7А: хорошая успеваемость, домашние задания частично сданы.

## Вымышленная школа

4 класса (7А, 7Б, 8А, 8Б), 60 учеников, 14 учителей, 10 предметов (в том
числе казахский язык и физкультура), 11 кабинетов, расписание без
пересечений, журнал с 5 октября по 2 ноября, закрытая первая четверть с
итоговой ведомостью, домашние задания со сдачами и проверкой, контрольная с
переносом в журнал, сообщения и объявления, форма (9 из 15 семей ответили),
консультации с записью, собрание класса, объяснительные об отсутствии
(принята, отклонена, ждёт решения), проверенные связи родителей с детьми,
замена и отсутствие учителя в день показа. Фамилии придуманы
(`tools/demo/names.py`); почт и телефонов нет. Прочитаны почти все
уведомления: непрочитанными остаются только три последних у каждой роли.

## Как обновить снимок

Только на временной базе. Данные школы (`data/`) не читаются, не
копируются и не указываются в `TIMETABLE_DB`: `tools/demo/clock.py` отказывает,
если путь внутри репозитория или содержит каталог `data`.

```powershell
npm ci
npm --prefix tools/demo ci
npx --prefix tools/demo playwright install chromium   # браузер для снятия и проверки
npm run build                      # frozen_server отдаёт dist
$work = "$env:TEMP/atlas-demo"     # любой временный каталог вне репозитория
.venv/Scripts/python -m tools.demo.seed_school --workdir $work        # около двух минут
.venv/Scripts/python -m tools.demo.check_seed --workdir $work
.venv/Scripts/python -m tools.demo.frozen_server --workdir $work --port 8765   # в отдельном окне
node tools/demo/capture.mjs --workdir $work --url http://127.0.0.1:8765          # около часа
node tools/demo/capture.mjs --workdir $work --url http://127.0.0.1:8765 --no-walk --merge --viewport phone
npm run build:demo
node tools/demo/verify.mjs --shots $work/shots     # все роли, 1280 и 375 px
python -m pytest -q tests/test_demo_snapshot.py
git add tools/demo/snapshot
```

В Linux и macOS вместо `.venv/Scripts/python` используйте `.venv/bin/python`,
а `$work` задайте как `export work=$(mktemp -d)`.

Запускайте тяжёлые шаги по одному: заполнение базы, затем сервер с браузером,
затем сборки. Вторая команда `capture.mjs` дополняет снимок запросами, которые
зависят от ширины экрана (например, сетка посещаемости на телефоне). `--merge`
добавляет к прежнему обходу, `--no-walk` оставляет только сценарии из
`tools/demo/journeys.mjs`, `--rescrub` заново очищает и записывает прежний
обход без браузера (сырой обход лежит в `<workdir>/raw-<роль>.json`, не в
репозитории).

Что попадает в снимок: обход меню (`walk.mjs`), сценарии показа
(`journeys.mjs`), недели и дни вокруг показа (`capture.mjs`, развёртка по датам
с 5 октября по 13 ноября) и карточки, которые приложение открывает из списков
(`fanout.mjs`): каждый урок выбранных дней, каждая ветка сообщений, каждый курс
в каждой четверти, итоговая ведомость по классам, результаты форм, консультации
по датам, домашние работы по журналу, месяцы календаря контрольных. Всё это
запросы GET с теми же адресами, что строит приложение; записи блокируются.

`capture.mjs` блокирует все записи, поэтому обход меню не меняет базу: до и
после обхода число строк в таблицах совпало, кроме записей входа и присутствия.
Перед записью файлов он заменяет секретоподобные значения и останавливается,
если в снимке есть пути, адреса, почта или хеши. Снимок читайте глазами
(таблица самых больших записей выводится в конце) перед коммитом.

Размер: каждый файл меньше 5 МиБ (предел `tools/check_repository.py`),
вместе не больше 12 МиБ, после gzip не больше 1 МиБ на роль: так браузер
получает файл с Pages, а разбор нескольких мегабайт JSON занимает доли секунды.
Сейчас файл администратора около 4,8 МиБ (около 0,3 МиБ после gzip), остальные
меньше 2 МиБ. Если администратор не помещается, сокращайте в `fanout.mjs`
итоговую ведомость (страницы по классам и предметам) и окно `calendar/day` в
`capture.mjs`, а не поля ответов. Размер проверяет `tests/test_demo_snapshot.py`;
тот же файл проверяет, что у каждого списка есть карточки (уроки, ветки, курсы,
домашние работы, формы).

Обновляйте снимок перед каждой презентацией и когда меняются ответы API: CI
собирает демо, но снимок сам не обновляет. Чтобы сменить дату показа, измените
`DEMO_NOW` в `tools/demo/school.py` и повторите шаги.

### Проверка собранного демо

`node tools/demo/verify.mjs` открывает собранное демо (`dist-demo`) в
Chromium на 1280 и 375 px по сценариям и «обходам» (`tours` в
`journeys.mjs`: каждая карточка урока трёх дней, каждый курс, каждая ветка,
каждая домашняя работа) и завершается с ошибкой при ошибке страницы, пропуске
в снимке, запросе к `/api`, который ушёл в сеть, или кнопке, которую демо
должно скрывать. Ключ `--walk` дополнительно кликает по меню так же, как
снятие, и печатает разделы, где остались пропуски (это не ошибка, а список
мест, которые стоит посмотреть).

## Что в демо не работает

- Любые сохранения: правки, публикации, записи на консультации, отправка
  сообщений, отметки «прочитано», выход. Записи на консультацию не остаётся:
  слот остаётся свободным.
- Экраны, которые меняют расписание на месте (планировщик, правила, составление,
  предпросмотр): видны данные, а предпросмотр и генерация отвечают ошибкой
  демо; решатель OR-Tools не запускается.
- Файлы и печать с сервера (CSV, XLSX, .ics, вложения, фото): вместо перехода
  показывается подсказка. Печать из окна браузера работает.
- Приём в школу, табло, проектор, публичный сайт, ссылки публикации,
  интерактивные уроки в реальном времени, веб-push.
- Скрытые разделы (библиотека, потерянные вещи, столовая, платежи, приём,
  сайт) и модули без данных (кружки, документы, передача детей, дежурства).
- «Пользователи и доступ»: список аккаунтов виден, приглашения и журнал
  доступа пусты (настоящие не снимаются); «Состояние сервера», «Публикация» и
  «Информационные экраны» скрыты.
- Даты и фильтры вне снимка дают понятную ошибку, а не неверные данные: дни вне
  5 октября – 13 ноября 2026 (подробное расписание школы по дням — только с
  26 октября), итоговая ведомость по сочетаниям класса и предмета для классов,
  кроме первого, и по статусам, строка ведомости с историей и доказательствами.
- Зрители далеко западнее UTC−6 могут увидеть предыдущую дату и пропуски в
  снимке.

### Известные недочёты вёрстки самого приложения

Они есть и в обычной сборке, поэтому в демо исправлены только накладкой в
`src/demo/bar.ts` (полоса демо, ряд кнопок аккаунта в одну строку на телефоне,
отступы диалогов), а настоящие исправления нужны отдельным запросом:

- Верхняя строка у администратора держит больше десятка кнопок аккаунта и
  модулей; на телефоне до содержимого страницы приходится долистывать.
- Шапка `.topbar` имеет фиксированную высоту 65 px и на узких экранах
  налезает на содержимое без накладки демо.
- На ширине 375 px страница прокручивается вбок на экранах администратора
  «Учебная нагрузка», «Классы и группы», «Учебный календарь», «Учителя»:
  таблицы и ряд вкладок шире экрана.

## Публикация

Сборка и выкладка — `.github/workflows/pages.yml` (при push в `main` и вручную).
Перед первым запуском владелец включает Pages: **Settings → Pages → Source:
GitHub Actions**. Без этого выкладка завершится ошибкой. Воркфлоу не снимает
данные и не использует секреты; он берёт готовый снимок из репозитория.
