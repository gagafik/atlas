# Атлас — расписание школы

Разрабатываемая школьная платформа с расписанием, личными кабинетами, журналом, домашними работами и сообщениями. React + TypeScript, Python/FastAPI, SQLite, OR-Tools CP-SAT. Полный функционал aSc Timetables и EduPage ещё не реализован; актуальный перечень — [FEATURES.md](FEATURES.md) и [EDUPAGE_ROADMAP.md](EDUPAGE_ROADMAP.md).

[Интерактивные занятия](INTERACTIVE_LESSONS.md): учитель открывает вопросы по очереди,
ученики отвечают с автосохранением, затем школа открывает разбор и результаты семье.
Поддерживаются рисунки, документы, аудио и видео из библиотеки, отдельный экран для проектора.

Для совместной разработки: [CONTRIBUTING.md](CONTRIBUTING.md). Для сервера с HTTPS: [DEPLOYMENT.md](DEPLOYMENT.md). Общие инструкции для Codex и Claude: [AGENTS.md](AGENTS.md). Репозиторий содержит код и искусственные тестовые данные; рабочая школьная база, списки и вложения в Git не входят.

## Запуск на Windows

Откройте PowerShell в папке проекта и выполните:

```powershell
.\start.ps1
```

Затем откройте http://127.0.0.1:8000. Остановка: Ctrl+C. При первом запуске нужны Python 3.12, Node.js 22+ и интернет для установки зависимостей. Готовая сборка работает локально. Аккаунты и роли реализованы; локальный режим без аккаунтов предназначен для работы на своём компьютере. Для публикации используйте серверную конфигурацию с обязательным входом и HTTPS из DEPLOYMENT.md.

- Уход детей: проверка взрослых школой, семейные заявки, подтверждение передачи сотрудником, отзыв разрешений, возвращение и история. По умолчанию выключен до настройки правил школы. См. [HANDOVER.md](HANDOVER.md).
- Просмотр расписания по классам, учителям, кабинетам и учебным группам.
- Личная неделя ученика: общие уроки класса и только его core/math/elective-группы; поиск, фильтр класса, CSV и печать. Переход из списка учеников по имени.
- Перенос уроков мышью, редактирование занятий и закрепление позиции. Предпросмотр перед применением и блокировка новых нарушений.
- Рабочее место составителя: сводная сетка классов, учителей и кабинетов по дню или всей неделе; связанные виды и подсказки доступных мест.
- Массовый перенос, копирование, обмен временем, закрепление и снятие с сетки; правки нагрузки, учителя, кабинетов и синхронных блоков.
- Справочники и недельная нагрузка; совместное преподавание с проверкой каждого учителя. Явные занятия без учителя/кабинета и группы без класса для совещаний.
- Основной кабинет из списка вариантов плюс постоянные помещения, занятые одновременно. Вместимость, численность класса/нагрузки, здания и направленные переходы между последовательными уроками учеников и преподавателей; всё учитывается при проверке и генерации. Неизвестная вместимость/численность/здание видны в отчёте. Несколько помещений одного занятия должны находиться в одном здании; распределение учеников по отдельным комнатам не моделируется.
- Смешанные группы со списками учеников, включая пересекающиеся группы из разных классов.
- Выбор курсов: секции на основе учебных групп, заявки и альтернативы по приоритету, обязательность и закрепление секции. Автораспределение с пределами численности, учётом существующего расписания всех недель и персональных ограничений; предпросмотр составов, применение и отмена. Пустой состав может быть явно подтверждён.
- Учебные циклы: отдельные недели A/B или другие шаблоны, часы и пары/тройки по каждой неделе, выбор активных недель нагрузки и правил. Учебные периоды со своим чередованием и опорным понедельником, выбор недели по дате. Копирование недели и генерация нескольких недель с общим предпросмотром; другие недели сохраняются.
- Проверка пересечений по фактическому времени (профили звонков младшей и старшей школы различаются).
- Редактор профилей звонков: основное время недели и отдельное время каждого дня, проверка конфликтов до применения. Время дня используется в генераторе, просмотрах и CSV. Удаление используемого профиля или периода блокируется.
- Подробные конфликты: время, конкретные ученики и классы, учителя, кабинеты; переход к обоим урокам, составам групп и личному расписанию. В личной проверке пересечение групп по другому ученику не считается его собственным конфликтом.
- Генерация на CP-SAT: учителя, группы, кабинеты, доступность, дневной предел по предмету, закрепления и синхронные блоки. Предпочтение ранним урокам и прежним позициям.
- Раздел «Ограничения»: доступность ресурсов по реальному времени, дневной минимум/максимум, начало и конец дня, свободные минуты между уроками, серии, непрерывный обед, число учебных дней и расстояние между ними. Условия класса применяются к каждому ученику и учитывают его смешанные группы.
- Связи двух наборов предметов: порядок в течение дня, запрет непосредственного следования, одинаковые/разные дни. Для классов учитываются предметы каждого ученика.
- Предел пустых учебных периодов и окон за день, сумма пустых периодов за неделю; отдельный профиль звонков и исключаемые периоды. Частичное пересечение с фактическим уроком означает занятость периода.
- Дополнительные правила бывают обязательными или пожеланиями с весом. Невыполненные пожелания и их штраф отображаются отдельно. При невозможности генератор может назвать несовместимый набор дополнительных правил (не обязательно минимальный).
- Пары и тройки: длины занятий в нагрузке, например 2 + 2 + 1, с пределом перемены внутри занятия. Генератор размещает части занятия в соседних периодах одного дня и одном кабинете; независимая проверка выявляет нарушение структуры.
- Фоновая локальная очередь генерации: до 600 секунд поиска, этап подготовки, число найденных решений, отмена, выбор произвольных нагрузок. Можно закрывать окно поиска. Независимая проверка, сравнение изменений и отдельное применение результата. Перемещённые занятия сохраняют идентификаторы и сведения об источнике.
- Отсутствие решения и истечение лимита времени различаются. При неудаче расписание не меняется. Очередь и отмены сохраняются в БД. После перезапуска оборванный поиск автоматически начинается заново с прежними параметрами; после трёх незавершённых запусков нужен ручной повтор. Изменение исходной версии останавливает устаревшее задание.
- SQLite, проверка версии при сохранении из нескольких окон, 30 предыдущих состояний, отмена и повтор, именованные варианты со сравнением и восстановлением, резервные копии JSON.
- «Обмен и печать»: CSV/XLSX выбранных расписаний, XLSX-таблицы всей базы, самостоятельный HTML и полная XML-копия с предпросмотром восстановления. Сетка, список или сводный плакат; пакет классов, учителей, кабинетов, групп или учеников по выбранным неделям, A4–A1, ориентация и состав карточек. Печать/PDF через браузер.
- Учебный календарь 2026/27 с явной отменой занятий для выбранных классов; фактические занятия по датам, отсутствия, подбор замен, переносы и разовые уроки.
- Отдельное демонстрационное пространство для проверки генератора без изменения школы.

## Как распределять учеников по курсам

В разделе «Выбор курсов» создайте курс и укажите его секции — уже существующие смешанные группы с подтверждённым составом. Секция принимает классы, перечисленные в группе. Установите минимум и максимум активных учеников; минимум 0 позволяет оставить секцию пустой. Секции и их учебная нагрузка создаются вручную.

Одна заявка ученика выбирает один курс из упорядоченного списка альтернатив. Для второго независимого курса нужна отдельная заявка. Необязательная заявка может остаться без назначения; закреплённая секция обязательна. Для перераспределения между прежним и новым курсом включите оба в альтернативы. Курсы за пределами альтернатив, а также ученики без выбранных заявок сохраняются. Заявки одного ученика с общими альтернативами нужно распределять вместе.

Поиск сначала максимизирует число назначенных заявок, затем улучшает приоритеты, затем предпочитает прежнюю секцию. Все уроки и составы остальных групп остаются на месте. Проверка учитывает фактическое время во всех неделях, известную вместимость, личные правила и переходы. Результат меняет базу только после просмотра и применения; доступна отмена. Если уроки секций ещё не размещены, их будущие пересечения проверить нельзя — число таких часов показывается отдельно. Составы едины на весь учебный год; совместного поиска новых составов и времени занятий пока нет. Заявки можно внести сотруднику или принять из личных кабинетов учеников/родителей через отдельное рассмотрение.

## Импорт таблиц

Откройте «Обмен и печать» → «Импорт таблиц». Выберите справочник или занятия, загрузите CSV/TSV, XLSX/XLS, HTML/MHTML либо плоский XML. Укажите лист, строку заголовков и соответствие колонок полям. Поле можно заполнить постоянным значением для всех строк. Шаблон CSV содержит основные поля выбранной таблицы; остальные доступны через «Показать все поля».

Выберите добавление, обновление или оба режима. Существующие записи сопоставляются по внутреннему ID, однозначному имени (ученик — вместе с классом) или внешнему ID ученика. Ссылки принимают ID или точное однозначное имя; сначала импортируйте справочники, затем связанные группы/нагрузки/занятия. Нагрузка не имеет имени: для ссылки на неё нужен ID. Списки допускают JSON или выбранный разделитель; сложные структуры требуют JSON с внутренними ID.

Нажмите «Проверить импорт», просмотрите изменения и примените их. До применения база не меняется. Строки, отсутствующие в файле, и несопоставленные поля сохраняются. По умолчанию пустые ячейки также сохраняют прежние значения. Ошибки строк можно скачать CSV; новые конфликты занятий блокируют применение. После применения доступна отмена. Повторный импорт обновляет найденные записи, но режим добавления без устойчивого ключа может создать новые.

Лимиты: 10 МБ, 20 000 строк, 200 колонок, 300 000 ячеек. Загруженный файл хранится в памяти сервера до 30 минут; перезапуск требует загрузить его повторно. Формулы XLSX в используемых колонках не вычисляются и отклоняются. Бинарный XLS предоставляет сохранённые значения формул. Макросы и скрипты не исполняются. Мастер ожидает по одной записи в строке: матрицы aSc и отметок элективов обрабатываются специализированными скриптами ниже. Полная XML-копия Атласа восстанавливается на вкладке «Копии всей базы»; .roz напрямую не читается.

### Проверка XML aSc во временной базе

Экспорт aSc Timetables 2012 XML можно загрузить только в отдельную временную базу, чтобы проверить расписание aSc и генератор Атласа. Рабочая база, `data/` и любые каталоги Git-репозиториев не принимаются; существующие базы Атласа не перезаписываются даже с `--force`. `--json` и `--report` не заменяют базы SQLite, исходный файл и друг друга, а прочие существующие файлы — только с `--force`.

```powershell
.\.venv\Scripts\python.exe -I tools\import_asc_xml.py 'C:\путь\asctt2012.xml' --db "$env:TEMP\asc\asc.db" --report "$env:TEMP\asc\report.json"
```

Отчёт содержит только количества. Экспорты с учениками или составами групп aSc пока отклоняются. Без составов по умолчанию (`--rosters synthetic`) создаются анонимные синтетические ученики, повторяющие пересечения делений aSc; вместимость кабинетов при этом не переносится. `--rosters none` оставляет группы делений без состава: пересечения подгрупп тогда не проверяются. `--period-policy observed` ограничивает уроки класса его последним уроком в aSc. Выделенным (например, нулевой урок) считается урок, где полностью размещённый урок aSc стоит не меньше двух раз и ни один урок не выходит за него: его уроки остаются в нём, остальным он закрыт. Уроки класса с неразмещёнными карточками не ограничиваются. `free` снимает все ограничения; `--rooms used` оставляет только кабинеты, реально стоящие на карточках.

Замеры на экспорте школы (967 уроков, 2540 карточек, 8 потоков CP-SAT): проверка находит 11 совпадений учителей за 0,3 с. Исправление с весами «стабильность 1, остальное 0» доказанно оптимально переносит 13 занятий за 44 с. Составление всей недели с нуля с допустимыми кабинетами aSc занимает 240–270 с и до 3,5 ГБ памяти, с `--rooms used` — около 30 с и 1,3 ГБ. С весами по умолчанию исправление за 180 с не доходит до оптимума, переносит 164 занятия и занимает до 5,3 ГБ.

## Замены и занятия по датам

Откройте «Замены и даты», выберите день и класс, учителя, кабинет или ученика. Неделя A/B определяется автоматически по учебным периодам. Можно отменить отдельный урок, изменить предмет и полный набор преподавателей/кабинетов, перенести на другую дату или добавить разовое занятие, в том числе в выходной. Недельные позиции и часы сохраняются. При переносе исходная дата показывает отменённый урок со ссылкой на новую дату; исходное время сохраняется, пока вы не измените его в форме.

«Указать отсутствие» задаёт учителя, диапазон дат и время отсутствия в каждом дне. Его можно сохранить с незакрытыми уроками: проверка даты перечислит занятия, требующие замены. В форме урока доступен подбор свободного преподавателя по сохранённому времени. Он проверяет занятость, отсутствие, обязательные запреты и переходы, но не подтверждает квалификацию. После изменения времени или других полей нужна общая проверка формы. Совместные преподаватели сохраняются при замене одного из них.

У каждого изменения есть предпросмотр; новые пересечения учеников/классов, учителей и кабинетов, нарушения вместимости, зданий, переходов и обязательной недоступности блокируют применение. Неполные составы и незаданные ресурсы показываются отдельно. Для фактических занятий также проверяются дневные минимум/максимум, начало/конец дня, окна, серии, обед и связи предметов. Пожелания с весом показываются в дне и предпросмотре и не блокируют применение. Минимум пустого дня не требует уроков у классов на каникулах или отсутствующего учителя; простая ручная отмена сама по себе не освобождает от минимума. В выходной/вне учебного периода минимум проверяется только при наличии фактических занятий. Недельные часы, распределение дней, сумма окон за неделю и синхронные блоки остаются правилами недельного шаблона. Результат доступен для отмены/повтора, удаления конкретного изменения и экспорта дня CSV. XML/JSON-копии и XLSX-таблицы включают изменения и отсутствия.

В «Учебном календаре» у периода выберите влияние на занятия: отметка или отмена. Явный список классов определяет область отмены; пустой список — все классы. Текстовая подпись «Для каких классов» сама ничего не отменяет. В смешанной группе исключаются ученики отменённых классов, остальные продолжают занятие. Собрания без класса не отменяются школьными каникулами. Все исходные школьные периоды сохранены как отметки до проверки дат и области отмены. Каникулы не сдвигают чередование недель.

Разовое изменение связано с исходным уроком и датой. Если правка или генерация недельного шаблона убирает этот урок либо меняет его день/неделю, предпросмотр сообщает об устаревшей связи. Сначала уберите или переназначьте такое изменение. Это предотвращает незаметную потерю замен при новой генерации.

## Экспорт и печать

В разделе «Обмен и печать» выберите тип расписания, все или конкретные записи и недели. XLSX расписания содержит плоскую таблицу занятий. HTML — самостоятельный документ без внешних ресурсов; его можно открыть и распечатать на другом компьютере. Личное расписание ученика включает общие занятия его класса и только его группы.

Для пакетной печати доступны сетка, список и сводный плакат. Укажите заголовок, размер A4–A1, ориентацию и нужные подписи. В сетке и списке каждая запись/неделя начинается с новой страницы, но большое расписание может продолжиться на следующем листе. Размер, масштаб и сохранение PDF окончательно выбираются в диалоге браузера. Документ показывает размещённые шаблоны недель; изменения по конкретным датам в этот экспорт пока не входят.

«Таблицы всей базы» выгружают все сущности в отдельные листы XLSX. Заголовки соответствуют именам полей, списки и объекты содержат JSON. Это обмен таблицами; для полного восстановления используйте JSON или XML. XML имеет собственную структуру Атласа, не совместим с aSc автоматически. Загрузка XML сначала показывает все изменения, затем заменяет базу по отдельному нажатию; предыдущая версия остаётся доступна для отмены. Прямое чтение .roz не реализовано.

## Бронирования и дежурства

В разделе «Бронирования и дежурства» создайте событие с датой, временем и кабинетами либо дежурство с местом и необходимым числом сотрудников. Можно указать несколько групп, явную численность посетителей, здание и примечание. Пустая численность вне известных составов остаётся непроверенной. Для запретов сотрудников по номеру урока выберите профиль звонков.

При создании доступны до 53 повторений с шагом 1–8 недель. Это отдельные записи: проверяется весь пакет, выход за учебный год отклоняет его целиком. Указанные даты действуют и во время каникул. Все сохранения проходят предпросмотр; новые нарушения блокируют применение. Кабинет или учитель освобождается при отмене соответствующего урока на дату. Закреплённую запись нужно разблокировать перед ручной правкой или удалением.

На вкладке «Дежурства» выберите записи и нажмите «Распределить выбранные дежурства». Поиск назначает требуемое число учителей из заданного списка кандидатов (пустой список допускает всех), сохраняет закреплённые назначения, учитывает фактические уроки, замены, бронирования, другие дежурства, отсутствие, недоступность, обед и переходы. Цель — выровнять суммарные минуты за диапазон выбранных дат, затем сохранить прежних дежурных. Уже назначенные дежурства в этом диапазоне входят в расчёт. Можно ограничить минуты на сотрудника; лимит действует для текущего поиска. Пожелания видны в проверке, но не входят в целевую функцию этого распределения. Квалификацию и состав допустимых сотрудников определяет школа.

Один поиск охватывает до 200 дежурств и 300 кандидатов, время поиска — до 30 секунд. Результат сохраняется только после отдельного применения. Незаполненные места показываются в проверке дня. События и дежурства занимают реальное время и обеденный перерыв, но не считаются учебными уроками в дневных лимитах, сериях и окнах между уроками. Неизвестные здания, вместимость и составы остаются отмеченными пробелами проверки. «Открыть день» показывает запись вместе с фактическим расписанием; из карточки можно вернуться к редактированию. Есть CSV выбранного диапазона, отмена/повтор и обмен XLSX/XML.

## Публикация расписания

В разделе «Публикация» выберите получателей по классу, учителю, кабинету, группе или ученику. Выбор явный, до 200 записей. Можно опубликовать повторяющиеся недели либо фактические занятия за 1–31 день с заменами, отменами, разовыми событиями и дежурствами. Сначала отображается точный документ, затем кнопка «Опубликовать этот снимок» создаёт отдельную ссылку. До этого просмотра по ссылке нет. Предпросмотр действует 30 минут, применяется один раз и отклоняется при изменении исходной версии базы.

Снимок не меняется при дальнейших правках: для нового расписания подготовьте новую публикацию и при необходимости отзовите прежнюю. Срок ссылки — 1–365 дней с момента публикации. По кнопке «Отозвать ссылку» сервер перестаёт отдавать документ; уже сохранённые получателями копии отозвать нельзя. Публикации хранятся отдельно от истории расписания в той же SQLite-базе и не входят в JSON/XML-копию состояния. Для их переноса сохраняйте всю базу.

Документ содержит выбранные названия и подписи уроков; список состава группы, причины отсутствия, заметки и исходные файлы туда не попадают. Личное расписание содержит имя выбранного ученика. Ссылка доступна любому, кто её получил, независимо от входа в систему. При текущем запуске на `127.0.0.1` ссылка открывается только на этом компьютере. Публикация не размещает данные в интернете и не настраивает сервер для других устройств. HTML можно напечатать средствами браузера.

## Учётные записи и совместная работа

Раздел «Пользователи и доступ» позволяет создать первого администратора и включить обязательный вход. До этого сохраняется прежняя локальная работа; запросы к рабочей базе извне компьютера не допускаются. Первый администратор создаётся на компьютере сервера. В рабочей школьной базе вход автоматически не включался: логин и пароль задаёт владелец через интерфейс.

Роли:
- **Администратор**: оба пространства, вся база, учётные записи и журнал действий.
- **Составитель**: редактирование только явно разрешённых пространств «Школа»/«Пример».
- **Учитель**: просмотр назначенных расписаний преподавателей.
- **Ученик**: одно назначенное личное расписание в каждом разрешённом пространстве.
- **Родитель**: личные расписания назначенных учеников.
- **Наблюдатель**: явно выбранные расписания классов, учителей, кабинетов, групп или учеников.

В форме доступа выберите записи и нажмите «Добавить область доступа», затем сохраните учётную запись. Личный кабинет показывает текущую рабочую версию недели или даты, включая отмены и разовые события, и поддерживает CSV/печать. Он получает только подготовленные поля своего расписания: без полной базы, списков состава, причин отсутствия и служебных заметок. Это отдельный сценарий от неизменяемых опубликованных снимков; их версия указана в документе.

Пароль содержит 12–128 символов, пробелы сохраняются. Проверочные значения хранятся с солью через scrypt; сессионные ключи — в виде SHA-256, cookie — HttpOnly/SameSite Strict, с Secure при HTTPS. Сеанс действует 12 часов, одновременно сохраняется не больше 10 сеансов записи. Вход ограничен по клиенту и логину при неудачных попытках. Изменение доступа, отключение записи или сброс пароля завершает её прежние сеансы; личная смена пароля оставляет только текущий сеанс. Последнего активного администратора нельзя отключить или понизить.

Составители видят присутствие других окон и пользователей (проверка каждые 25 секунд, запись истекает через 75 секунд). При сохранении новой общей версии появляется предложение загрузить её. Неприменённые формы закрываются только по явному нажатию, автоматического слияния данных нет. Защита версии на сервере отклоняет устаревшее сохранение. Журнал хранит автора, пространство и точную версию сохранения, отмены/повтора, а также действия доступа и входа — последние 10 000 записей. Это журнал действий, не учебный журнал оценок/посещаемости.

Учётные записи, сеансы и журнал хранятся в SQLite отдельно от состояния расписания: JSON/XML-восстановление не меняет права доступа. Для полного переноса сохраняйте SQLite-базу. Если утрачен пароль администратора, владелец компьютера может выполнить локальную команду; она запросит новый пароль без отображения и завершит прежние сеансы:

```powershell
.\.venv\Scripts\python.exe tools\reset_account_password.py login
```

Настройка сети, HTTPS и внешнего размещения не включается созданием аккаунтов. `start.ps1` по-прежнему слушает только `127.0.0.1`. Для другого развёртывания сервер должен быть доступен по защищённому адресу; при отдельном адресе интерфейса разрешённые источники задаются через `TIMETABLE_ALLOWED_ORIGINS` (список точных origin через запятую). Встроенного SMTP/SSO/восстановления по электронной почте нет.

## Хранение

### Подключение родителей по приглашению

После включения учётных записей администратор открывает **Пользователи и доступ → Пригласить пользователя**, задаёт получателя, роль (родитель, ученик или учитель), конкретных детей/преподавателя и срок действия 1–30 дней. Код показывается только при создании; передайте его лично проверенному получателю. Отправка email/SMS не подключена.

На экране входа получатель выбирает **Создать аккаунт по приглашению**, вводит код и задаёт собственный логин/пароль. Для второго ребёнка родитель входит в существующий аккаунт и нажимает **Принять приглашение**; после подтверждения текущего пароля доступ объединяется, прежние сеансы завершаются. Другому представителю выдаётся отдельное приглашение. Ученику нельзя добавить чужую запись в том же пространстве; приглашение не меняет роль существующего аккаунта.

Приглашение можно отозвать до принятия. Уже принятый доступ изменяется в учётной записи пользователя. Код одноразовый, хранится в БД только в виде хеша; есть срок действия, ограничение попыток и история выдачи/отзыва/принятия. Контакты и полномочия представителя проверяет школа; самостоятельное восстановление через email/телефон и массовая выдача ещё не реализованы.

### Рабочие файлы

`data/timetable.db` — рабочая база и история, `data/imported-school.json` — начальные импортированные данные. Сохраняйте эту папку при переносе проекта. При первом открытии школьного пространства данные берутся из JSON, последующие открытия используют SQLite. Изменение исходного JSON не перезаписывает рабочую базу.

Повторный разбор исходного файла в начальный JSON:

```powershell
.\.venv\Scripts\python.exe tools\import_timetable.py 'C:\путь\Classes_Summary.xls'
```

Новый JSON можно восстановить через Настройки → Восстановить. Исходный Excel-файл не изменяется.

Повторный импорт составов (зависимости уже входят в обычную установку):

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-import.txt
.\.venv\Scripts\python.exe tools\extract_rosters.py --core 'C:\путь\Группы.xlsx' --electives 'C:\путь\electives.mhtml' --output data\rosters.json
.\.venv\Scripts\python.exe tools\import_rosters.py data\rosters.json --rules data\roster-rules.json
# После проверки data/roster-import/report.json:
.\.venv\Scripts\python.exe tools\import_rosters.py data\rosters.json --rules data\roster-rules.json --apply
```

`--rules` необязателен: локальный файл содержит только явно подтверждённые школой объединения групп и переименования. Без `--apply` выполняется предварительная сверка. При сохранении API проверяет версию документа, оставляет резервную копию и запись для отмены. Существующие отличающиеся составы автоматически не перезаписываются. Повторный импорт тех же файлов не создаёт дубликатов. Сохранённые страницы разбираются без выполнения JavaScript и без обращения к EduPage.

После уточнений школы от 13.10.2026 прежние исходные списки отличаются от подтверждённых составов. Их повторный импорт остановится на проверке расхождения; сверяйте новые списки с `data/confirmed-rosters/confirmation.json` перед импортом.

Если новый экспорт отличается только подписями учителей, применяйте отдельное обновление вместо полного восстановления JSON:

```powershell
.\.venv\Scripts\python.exe tools\update_teachers.py --previous 'C:\путь\Classes_Summary.xls' --source 'C:\путь\Classes_Summary (1).xls'
# После сверки data/teacher-update/report.json повторите команду с --apply.
```

Сначала проверяются набор и содержимое всех исходных ячеек. При других изменениях, нескольких учителях внутри одной нагрузки, неоднозначном объединении, локальном переназначении или неизвестной принадлежности ограничений доступности обновление останавливается. Подтверждённые ранее полные имена сохраняются, если соответствующие подписи в новом экспорте не менялись. Перед сохранением остаётся JSON-копия; само сохранение защищено проверкой версии и доступно для отмены.

## Учебный журнал

Раздел **Учебный журнал** доступен локальному владельцу и администратору; в личном кабинете учитель видит свои фактические занятия. Выберите дату и урок, заполните тему, домашнее задание и срок, отметьте посещаемость. Для урока можно добавить до десяти проверочных работ: баллы с максимумом и весом либо текстовую оценку. Ноль отличается от отсутствия оценки; посещаемость изначально не отмечена. Можно указать минуты опоздания и индивидуальные комментарии.

**Сохранить черновик** меняет только рабочую запись. **Опубликовать** обновляет копию, которую видят ученик и родители с назначенным доступом к нему. Последующая правка черновика не меняет опубликованную копию. Посещаемость и оценки публикуются в день урока или позже по времени школы (Asia/Qyzylorda); тему, домашнее задание и материалы будущего урока можно опубликовать заранее. Черновик с отметками сохранить можно. Перенос оценки за домашнее задание или тест в журнал будущего урока также ждёт дня урока. Публикацию можно отозвать; история всех сохранённых редакций остаётся. Уведомления об изменении личной записи не содержат оценок и комментариев. Составитель и наблюдатель к учебному журналу доступа не получают.

После переноса урока или изменения состава интерфейс предлагает явно обновить время и состав перед сохранением. Выбывшие ученики и их оценки сохраняются, новые ученики получают пустые записи. Изменение предмета или группы создаёт отдельный журнал; старые оценки не переносятся на другой предмет. Отменённые и удалённые занятия доступны для чтения истории и отзыва публикации. Прежний преподаватель может прочитать свою запись, но править текущее занятие может назначенный преподаватель.

Отчёт за период показывает опубликованные записи выбранного ученика, посещаемость и средневзвешенный процент по числовым работам. Формула: сумма `(баллы / максимум × 100 × вес) / сумма весов`; работы с нулевым весом и текстовые оценки в процент не входят. Это не итоговая оценка и не преобразование в школьную шкалу. Отчёт открывается за последние 30 дней и 14 дней вперёд в пределах учебного года и загружается страницами по 100 записей (порядок: дата, время, ключ урока); итоги за выбранный период приходят с первой страницей, «Показать ещё» добавляет следующие. Кнопки «Последние 30 дней» и «Весь учебный год» меняют период. CSV и печать сначала загружают весь период (до 40 страниц); если записей больше, показывается просьба сократить период и частичный файл не создаётся. Личные роли не получают чужие составы и записи.

Журнал хранится в SQLite отдельно от состояния расписания, со своей защитой версии. Отмена/повтор расписания и его JSON/XML-восстановление не стирают оценки, но могут потребовать сверки состава и времени. Для резервной копии всего приложения нужна SQLite-база, а не только экспорт расписания.

## Уведомления и установка на устройство

В шапке приложения и личного кабинета доступны **Уведомления** и **Приложение**. Список уведомлений хранится на сервере отдельно от расписания: до 90 дней и 500 записей на пользователя. Есть счётчик, фильтр непрочитанных, постраничная загрузка и отметки прочтения. «Прочитать все» относится к показанной границе списка и не помечает изменения, пришедшие после неё. Отключение новых уведомлений сохраняет старую историю.

Сохранение, отмена и повтор записывают уведомления атомарно с версией расписания. Администраторы получают изменения обоих пространств, составители — разрешённых им. Личные роли получают изменения назначенных расписаний: сравниваются видимые недельные занятия и связанные изменения по датам. Для интервалов отсутствия/отмены используется затронутая аудитория, поэтому сообщение возможно даже при пустом конкретном дне. Это сообщение о необходимости проверить текущую рабочую версию, а не подробная рассылка содержимого уроков. Изменение имени частной причины, закрепления урока или чужого списка само по себе не отправляет сообщение ученику. Смена роли/прав скрывает прежнюю историю; смена пароля её сохраняет. JSON/XML-копии расписания не содержат уведомления и настройки, для полного переноса нужна SQLite-база.

Разрешение системных уведомлений запрашивается только кнопкой. Включение действует для текущей вкладки и версии учётной записи; список опрашивается примерно каждые 25 секунд, когда окно списка закрыто, и при возвращении в приложение. Уведомления ОС имеют общий текст без имён, предметов и причин. Нужны поддерживающий браузер, защищённое соединение и активный service worker. Закрытая/приостановленная браузером вкладка не получает новые события: фонового Web Push, email и SMS здесь нет. Автоматическая отправка внешних сообщений не выполняется.

Сборка `npm run build` содержит manifest, значки 192/512 и service worker. Браузер может предложить установку; доступное приглашение появляется в разделе «Приложение», иначе используются пункты меню браузера. На другом устройстве нужен доступный адрес сервера с HTTPS: `127.0.0.1` обозначает само устройство. Установка и системные уведомления на физических Android/iOS устройствах отдельно не проверялись; headless Chromium по умолчанию запрещает разрешение уведомлений.

При недоступности сервера навигация на главную показывает публичный экран подключения с кнопкой повтора. Кэш содержит только `offline.html`, manifest и два значка. API, страницы опубликованных снимков, списки учеников и расписания в кэш не помещаются. Сетевые ошибки записи не создают очередь отложенных изменений — повтор выполняет пользователь. Новая версия service worker ждёт закрытия старых окон, не перезагружая незавершённые формы. В режиме Vite dev service worker не устанавливается.

Технические основания: [MDN: автономная работа PWA](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Offline_and_background_operation), [MDN: разрешение уведомлений](https://developer.mozilla.org/en-US/docs/Web/API/Notification/requestPermission_static).


## Приоритеты и диагностика генератора

В окне «Составить расписание» для каждого запуска задаются веса ранних уроков, сохранения прежних позиций и множитель пожеланий. Диапазон 0–1000; ноль отключает предпочтение, не меняя обязательные условия. Исходный баланс — 2 / 3 / 1. Режим «Меньше перестановок» — 0 / 100 / 1, «Любой допустимый вариант» — все нули. Это взвешенная сумма, а не строгая очерёдность: большой суммарный штраф пожеланий может перевесить сохранение одной позиции.

Результат сохраняет выбранные веса и сравнение часов, суммы индексов периодов (с нуля), новых позиций и штрафа пожеланий. Новая позиция — сочетание нагрузки, дня, периода и кабинета, которого не было в исходном расписании; это не число изменённых карточек. Счётчики часов и позиций относятся к выбранной нагрузке; пожелания учитывают всю выбранную неделю, включая фиксированные уроки. Для неполного/недопустимого исходного варианта меньший штраф не означает допустимость. Генерация нескольких недель суммирует эти показатели.

После доказанной невозможности генератор разбирает отдельную копию модели. Он может назвать несовместимые часы, доступные позиции, дневные лимиты, ресурсы, закрепления, фиксированную занятость вне области поиска, синхронные блоки, длины занятий, переходы и дополнительные правила. Набор причин достаточен при исходных допустимых периодах/кабинетах, но не обязательно минимален. Диагностика не отключает условия в рабочем расписании и не применяет ослабленные решения.

Разбор ограничен 10 секундами подготовки и 10 секундами поиска (для коротких запусков — меньше), 250 000 исходных условий и 200 000 копируемых интервалов. При достижении предела приложение честно сообщает, что детальное объяснение не завершено. Тайм-аут основного поиска не считается доказательством невозможности. Подготовка основной модели и независимая проверка результата выполняются сверх заданного времени поиска.


## Встроенный AI-помощник

Раздел **AI-помощник** доступен администратору и составителю разрешённого пространства. Он использует API Ollama. На текущем компьютере рабочая языковая модель пока не обнаружена: интерфейс, обработка протокола и проверка предложений готовы, но качество реальных ответов ещё не испытано. Браузерная проверка выполнена на отдельном стенде с явно обозначенным фиксированным ответом.

Установите Ollama и подходящую вашей машине модель, запустите сервер, затем нажмите «Проверить подключение». По умолчанию используется `http://127.0.0.1:11434`; список моделей читается через `/api/tags`, ответ запрашивается через `/api/chat` с `stream: false` и JSON-форматом. Можно ввести точное имя уже установленной модели. Приложение не скачивает модели автоматически.

Параметры процесса сервера: `ATLAS_AI_URL` — корневой адрес Ollama (без `/api`), `ATLAS_AI_MODEL` — начальное имя модели, `ATLAS_AI_KEY` — необязательный ключ Bearer. Ключ не возвращается в интерфейс и не включается в запрос к модели. Для внешнего адреса требуется HTTPS. HTTP-прокси из окружения и перенаправления отключены. Источники протокола: [Ollama Chat](https://docs.ollama.com/api/chat) и [список моделей](https://docs.ollama.com/api/tags).

Сначала введите вопрос и выберите до 30 нагрузок. «Подготовить запрос» не обращается к модели: показывает точные вопрос и контекст. Контекст содержит общие счётчики проверки, выбранные нагрузки, связанные названия учителей/классов/предметов/кабинетов, звонки и до 500 выбранных занятий. Идентификаторы заменяются локальными обозначениями. Вместо списков учеников — только число общих участников групп; оценки, причины отсутствия, исходные файлы и частные примечания не включаются. Подробные правила, переходы и занятия вне выбора не передаются: итоговую допустимость проверяет редактор, а модель должна учитывать неполноту контекста.

«Отправить модели» обращается только к показанному серверу. Внешний адрес или имя модели с `cloud` требует отдельного разрешения для этого подготовленного запроса. Фактическая маршрутизация и хранение на сервере модели зависят от его настроек. Каждый запрос самостоятельный; предыдущая беседа автоматически не передаётся. В приложении запросы/ответы хранятся только в памяти до 20 минут, доступны своему пользователю и исчезают после перезапуска. Есть явная очистка. Одновременно обрабатываются не более двух обращений, ответы ограничены размером и временем; автоматического повторного запроса нет.

Модель может предложить новое правило, перенос или обмен выбранных занятий. Она не может удалить правила, снять закрепления, изменить оценки/составы или выполнить произвольный код. Сервер проверяет параметры и ссылки; затем пользователь нажимает «Проверить изменения» и отдельно применяет результат обычного редактора. Область синхронного переноса может включать связанные занятия — это видно в сравнении. После любой новой версии расписания нужен свежий запрос. Ответ модели не является доказательством отсутствия конфликтов и не подтверждает выполнение действий.


## Приём предпочтений учеников

В «Выбор курсов → Приём из личных кабинетов» составитель выбирает опубликованные для приёма курсы, максимум заявок и альтернатив, сообщение ученикам и необязательную дату окончания. Приём открывается явно; по умолчанию он закрыт. Срок включителен и проверяется по дате компьютера сервера. Ученику показываются только курсы с секциями, допускающими его класс.

В личном кабинете ученика/родителя есть «Выбор курсов». В одной заявке альтернативы расположены от наиболее желаемой к запасным; стрелка поднимает приоритет. Для двух независимых курсов нужны две заявки. Один курс не повторяется в разных заявках одного ученика. Родитель выбирает только назначенных ему детей. Отправка предпочтений не меняет расписание, прежние группы и рабочие заявки составителя. Пустой список отправляет просьбу об отзыве предпочтений.

Входящие сортируются сначала по ожидающим рассмотрения; есть страницы по 100 записей. Составитель может вернуть заявку с обязательным комментарием или проверить перенос в план. Только отдельное применение записывает рабочие CourseRequest и решение одной транзакцией. Смена предпочтений, условий приёма, прав или версии расписания отклоняет устаревшее применение. Ручные заявки сотрудника сохраняются. Прежнее закрепление секции нужно отдельно рассмотреть в редакторе. Новые заявки обязательны по умолчанию; составитель может изменить этот режим перед распределением.

Рассмотрение доступно и после закрытия приёма, пока выбранные курсы остаются допустимыми по действующим настройкам. Приём не гарантирует место: распределение по секциям запускается отдельно и учитывает вместимость, альтернативы и пересечения. Отзыв предпочтений не удаляет ученика из уже назначенной учебной группы.

Условия приёма, исходные предпочтения, решения и история редакций хранятся в SQLite отдельно от расписания. Отмена/повтор рабочего плана не стирает решение; интерфейс отдельно показывает, присутствует ли последний принятый вариант в текущем плане. JSON/XML-экспорт расписания содержит перенесённые CourseRequest, но не входящие обращения и настройки приёма. Для полного переноса нужна SQLite-база.


Проверка генератора на копии школьных данных (13.10.2026): 838 из 924 нагрузок с заполненными назначениями, 2296 уроков, пустая сетка выбранной нагрузки, остальные 244 занятия фиксированы. После оптимизации модели найден допустимый вариант за 6,125 секунды, независимая проверка — 0 найденных нарушений. До изменения представления интервалов такой поиск не находил вариант за 30 и 90 секунд. Это отдельный замер на этом ноутбуке, а не гарантия времени для других наборов. Неучтённые назначения, вместимость и ещё не заданные школьные ограничения по-прежнему требуют уточнения; результат не применялся к школе.

## Ресурсы генератора и фоновые запросы

С 14.10.2026 основная генерация, включая `/api/generate` и очередь, исполняется в отдельном дочернем процессе. Он получает снимок, а БД и применение результата остаются в API. По умолчанию решатель использует до двух потоков (один на одноядерной машине). Для настройки перед запуском сервера можно задать `$env:ATLAS_SOLVER_WORKERS='2'`; значение ограничивается диапазоном 1–16 и количеством логических CPU. Некорректная строка возвращает безопасное значение по умолчанию. Более высокое число потоков не гарантирует более быстрый поиск.

Фоновая очередь хранит параметры, состояние и число запусков в SQLite. При запуске API она восстанавливается без открытого браузера. Исполнитель подтверждает владение примерно раз в секунду; после аварийной остановки его право на задание истекает через 15 секунд. Оборванный поиск запускается заново, состояние внутреннего решателя не продолжается с контрольной точки. Максимум — три запуска одного задания, после чего оно помечается прерванным. При обычной остановке освобождение происходит сразу после завершения дочернего процесса. Отменённые пользователем задания не возобновляются. Старые задания без сохранённых параметров остаются прерванными.

Перед сохранением результата повторно проверяются владение заданием, отмена и версия расписания. Предпросмотр и окончательный статус записываются одной транзакцией. Исходное расписание не меняется до отдельного применения. Два координатора одной локальной БД не получают один слот одновременно; это ещё не разрешение запускать всю платформу в нескольких API-процессах: синхронные поиски курсов/дежурств, другие блокировки и временные состояния требуют дальнейшей общей координации. SQLite-файл не размещать на сетевом общем диске для распределённой очереди.

Проверка аварийного восстановления на отдельной искусственной школе:

```powershell
.venv/Scripts/python.exe -m tools.verify_generation_recovery --output data/feature-qa/queue-recovery.json
```

Инструмент запускает два фоновых поиска, аварийно завершает свой тестовый API после начала работы настоящего дочернего решателя, запускает API снова и проверяет автоматическое восстановление, два предпросмотра и полную неизменность исходного документа. Рабочую школьную базу он не использует.

Пониженный приоритет процесса оставляет системе возможность предпочитать другие задачи. Это не жёсткая квота CPU или RAM: такие ограничения ещё нужно настроить при размещении. Общий предел времени вычисления — выбранный лимит поиска плюс 120 секунд на подготовку/проверку. При отмене генератор получает сигнал, а через три секунды незавершённый процесс принудительно останавливается; результат отменённого поиска не применяется. При исчезновении родительского процесса дочерний прекращает работу. Результаты успешного поиска по-прежнему проверяются и применяются через защищённый версией предпросмотр.

Скрытые вкладки приостанавливают опрос авторизации, присутствия и генератора. Лента уведомлений тоже приостанавливается, кроме явно включённых системных уведомлений для открытой вкладки. При возвращении к вкладке или восстановлении сети обновление возобновляется. Запросы одного опроса не перекрываются, ошибки увеличивают паузу, а небольшой случайный сдвиг распределяет обращения клиентов. Генератор проверяет активный поиск примерно раз в 1,5 секунды, отсутствие поиска — раз в 30 секунд. Полноценный push при закрытом приложении пока не реализован.

Всё приложение пока рассчитано на **один API-процесс**. У очереди расписания уже есть общий слот владения в локальной БД, но другие задачи и временные предложения ещё локальны процессу; не увеличивайте число API-процессов без следующего этапа координации.

## Отправка и проверка домашних работ

Учитель публикует задание и срок в журнале урока. В личном журнале ученик нажимает «Открыть домашнюю работу», пишет ответ и при необходимости прикрепляет файлы. «Сохранить черновик ответа» сохраняет частный вариант; учитель и родитель его не видят. После «Отправить работу» ответ становится доступен действующему учителю и родителю, связанному с этим учеником. До проверки ученик может отозвать ответ, после возврата учителем — отправить исправление. Прежние отправки и вложения остаются в истории.

В журнале учителя кнопка «Домашние работы учеников» показывает состав и статусы. Учитель принимает работу или возвращает её с обязательным комментарием. Принятие без выбранной оценки подтверждает только проверку. Чтобы сразу выставить оценку, включите «Выставить и опубликовать оценку при принятии»: выберите существующую работу или создайте новую, укажите баллы либо текстовую оценку. Для замены уже имеющейся оценки нужно подтвердить показанные опубликованное и черновое значения. Новая работа появляется у всего урока, но оценка записывается только выбранному ученику. Баллы соблюдают максимум и вес работы; текстовые оценки и работы с весом 0 не входят в средний процент.

Оценка и принятие сохраняются одной операцией. Оценка сразу доступна ученику и родителям; остальные черновые поля журнала не публикуются. При сохранённом черновике создаются две последовательные редакции: публикация с оценкой и черновик с остальными полями. Несохранённые поля на экране не стираются; перед последующим сохранением нужно открыть актуальную редакцию. Закрытый период запрещает выставление оценки, но допускает обратную связь без неё. Изменённые параметры работы или состав урока сначала согласуйте в журнале. Если кто-то изменил журнал одновременно, обновите параметры оценки и проверьте значения перед повторной отправкой.

В ответе и истории сохраняется оценка на момент проверки. Последующие исправления видны в журнале; возврат задания не удаляет записанную оценку. Отправка и отзыв уведомляют назначенного учителя, результат проверки — ученика и его родителей. Изменение текста, срока, материалов или правила приёма задания требует новой отправки; старый ответ помечается как относящийся к прежним условиям. После отмены занятия доступны прежние записи, но не отправка и проверка. Отзыв публикации закрывает доступ к домашней работе и её файлам, сохраняя их в базе.

Срок включителен до конца дня в `Asia/Qyzylorda`. По умолчанию поздние ответы принимаются с отметкой «после срока»; учитель может закрыть приём после срока. В одном ответе до 10 000 символов и пяти файлов по 10 МиБ: PDF, PNG/JPG, TXT, DOCX/XLSX/PPTX. Лимит ученика — 250 МиБ на пространство; одного задания — 30 файлов с учётом истории. У раздела свой бюджет (`ATLAS_UPLOAD_HOMEWORK_MB`, по умолчанию 30 ГиБ) под общим пределом `ATLAS_UPLOAD_TOTAL_MB` и запасом свободного места на диске; значения и очистка — в [DEPLOYMENT.md](DEPLOYMENT.md#хранилище-файлов). Одновременно принимаются 16 загрузок на API (`ATLAS_UPLOAD_SLOTS`), ещё до 64 ждут в очереди до 15 секунд; при занятом сервере ответ 429 с `Retry-After`, и форма сама повторяет загрузку («Сервер занят, повторяем…»). Не более двух текущих загрузок на ученика; перед загрузкой резервируется максимальный размер, время приёма ограничено 90 секундами. JPEG/PNG длиннее 2560 px или тяжелее 3 МиБ браузер уменьшает до JPEG (качество 0,85, ориентация сохраняется, метаданные не передаются); при ошибке отправляется исходный файл.

Файлы находятся в каталоге рядом с БД: для `data/timetable.db` это `data/timetable.files/homework`. В документ расписания они не включаются. Прямая публичная раздача каталога запрещена: скачивание проходит проверку аккаунта, ученика, задания и опубликованного доступа. Сервер проверяет расширение и начальную сигнатуру, выдаёт файл как вложение без исполнения в странице. Это не полная проверка формата и не антивирус. Незавершённые загрузки старше 30 минут и неиспользованные готовые файлы старше суток очищаются порциями при последующих загрузках; сохранённые черновики и история защищены от этой очистки.

Записи и файлы открываются по запросу пользователя, без фонового опроса каждого задания. Расчёт занятий дня повторно используется до изменения версии расписания; права, публикация и редакции ответов проверяются заново. Нагрузочный сценарий сдачи/проверки/скачивания и его ограничения описаны в [PERFORMANCE.md](PERFORMANCE.md).

### Материалы задания и закрытие приёма

В журнале учитель прикладывает до пяти материалов по 10 МиБ, выбирает срок
и правило поздней сдачи. По умолчанию поздние ответы разрешены с отметкой.
«Закрывать приём после срока» запрещает отправку с 00:00 следующего дня по
времени `Asia/Qyzylorda`; API проверяет время внутри транзакции отправки.
Черновики и файлы ответа можно сохранять после срока. Возврат на доработку
не продлевает срок автоматически: учитель должен изменить дату или разрешить
поздние ответы и опубликовать изменение. При отзыве после срока ученик видит
предупреждение, что повторная отправка пока закрыта.

Загрузка материала сама по себе не публикует его. Выбор файлов сохраняется
с журналом; ученики и их родители получают доступ после публикации. Материалы,
текст, срок и правило приёма входят в версию задания. Прежняя отправка сохраняет
свои условия и файлы; их можно открыть в истории работы. Учитель видит материалы
сохранённых редакций журнала. Ученик, не отправлявший прежний вариант, не получает
доступ к удалённым материалам только из-за участия в текущей группе.
Отзыв публикации закрывает семейный доступ ко всем файлам этого задания.

Материалы хранятся в `<имя базы>.files/assignments`, входят в полную копию
с проверкой хешей и используют общие места загрузки (16 на API, очередь до 15 секунд),
свой бюджет раздела `ATLAS_UPLOAD_ASSIGNMENTS_MB` и общий предел диска со всеми
остальными вложениями. Одинаковые файлы хранятся один раз (по SHA-256 и размеру):
у каждой записи свои права доступа, файл удаляется, когда на него не ссылается ни
одна запись, а квота автора считает его один раз. Дополнительно: 250 МиБ на автора, до 100 файлов
на урок с учётом истории, до двух текущих загрузок автора и 90 секунд на файл.
Готовые файлы без сохранённой редакции старше суток постепенно очищаются;
все сохранённые редакции, включая черновики, удерживают свои материалы.
Проверка расширения/сигнатуры не заменяет антивирус. Индивидуальные продления,
оценка из формы проверки и сводная очередь заданий пока не реализованы.

## Полная резервная копия

Сообщения, получатели, прочтение и подтверждения хранятся в отдельных таблицах той же SQLite-базы и входят в её полную резервную копию. Экспорт JSON/XML расписания их не содержит.

JSON/XML расписания и отдельная копия SQLite не включают бинарные вложения. Для полной локальной копии используйте:

```powershell
.venv/Scripts/python.exe -m tools.backup_school
```

Команда создаёт новую папку в `data/backups` с согласованным снимком SQLite, готовыми вложениями и `manifest.json`, содержащим контрольные суммы. Можно указать `--database путь/к/базе.db --output новая/папка`. Существующая папка не перезаписывается. На время копирования запись в исходную БД блокируется, чтение остаётся доступным; запускайте в тихое время, а при большом объёме файлов — с остановленным сервером. Незавершённые загрузки не включаются; рабочая база не меняется. Ошибка чтения или проверки оставляет неполную папку без `manifest.json`, её нельзя считать готовой копией.

Для восстановления остановите сервер, сохраните текущую базу отдельно, проверьте хеши по манифесту и используйте копию базы **вместе с одноимённым каталогом `.files`** из резервной папки, сохранив имя базы. Можно направить `TIMETABLE_DB` на базу в отдельной восстановленной папке. Не подменяйте файл работающей SQLite-базы и не смешивайте его со старыми файлами WAL/SHM. Копия содержит персональные записи и данные доступа: храните её в закрытом месте. Автоматического расписания копий и внешнего хранилища пока нет.

## Сообщения и объявления

Раздел «Сообщения» появляется в личных кабинетах и в рабочем интерфейсе сотрудников. Для переписки нужны реальные учётные записи: локальный режим без входа не создаёт фиктивного адресата. «Написать сообщение» открывает личный диалог: выберите ученика, доступного собеседника, тему и текст. Семье доступны администраторы и учителя, назначенные учебной нагрузке её ребёнка, включая совместных преподавателей и смешанные группы. Родитель не получает список других семей. Сотрудники могут переписываться между собой без привязки к ученику. Временная замена отдельного урока пока не добавляет нового собеседника автоматически.

Доступ к личному диалогу есть только у двух участников; администратор вне диалога не получает доступ к тексту через этот раздел. Право на ребёнка, активность аккаунтов, роли и текущая учебная связь проверяются при каждом запросе. Потеря этой связи закрывает доступ к диалогу, сохраняя записи в базе. Если связь восстановлена, история снова доступна. Изменение пароля само по себе не стирает историю. Автор может закрыть ответы и затем открыть их снова.

Учитель может выбрать «Объявление» для своих учебных групп, отдельно указать учеников и/или родителей. Администратор также может выбрать всю школу и роли сотрудников. «Проверить получателей» показывает число активных аккаунтов; один аккаунт в нескольких выбранных группах получает объявление один раз. Получатели определяются окончательно при отправке и затем не пополняются автоматически. Объявление не имеет общего обсуждения: получатель может начать отдельный личный диалог. Список получателей и состояния прочтения видны автору, обычный получатель видит только само объявление.

Открытие переписки отмечает показанные сообщения прочитанными. Это не означает согласие: для объявлений с флажком «Попросить подтвердить ознакомление» есть отдельная кнопка подтверждения. Автор может отозвать объявление: у получателей оно скрывается, история автора остаётся. Редактирования уже отправленного текста пока нет; исправление отправляется отдельным сообщением или новым объявлением.

Есть поиск по теме и тексту, фильтр непрочитанных и страницы истории. Тема ограничена 160 символами, текст — 10 000, отправка — 30 сообщений за 5 минут на аккаунт. Повтор одного запроса с тем же идентификатором не создаёт дубль. Одновременные ответы в одной переписке сохраняются все, по порядку записи: версия переписки меняется только со статусом, участниками и управлением, а не с каждым ответом; ответ в закрытую переписку отклоняется. Уведомления не содержат текст сообщения или имя ученика. Входящие обновляются при открытии и по кнопке; постоянного опроса каждой переписки нет, поиск отправляется после короткой паузы ввода. Жалобы и модерация остаются следующими этапами.

### Личные черновики сообщений

Кнопка «Сохранить черновик» сохраняет текст, тему, выбор адресатов и отмеченные вложения на сервере. Это работает для личных диалогов, групп, объявлений и ответов. Можно сохранить неполную форму без темы или получателей. До 50 черновиков на аккаунт в каждом пространстве; раздел «Черновики» позволяет продолжить работу после перезагрузки или с другого устройства и удалить ненужное. Черновики доступны только владельцу, включая доступ через API; администратор не получает доступа к чужим черновикам. Сохранение не отправляет уведомлений получателям.

Сохранение выполняется **по кнопке**, автоматического сохранения и офлайн-очереди нет. Форма показывает несохранённые изменения. При конфликте двух устройств сервер не перезаписывает другую редакцию: текущий текст остаётся в форме, его можно скопировать перед открытием актуальной версии. При отправке вновь проверяются получатели, права и версия черновика; сообщение и закрытие черновика записываются атомарно. Повтор отправки не создаёт дубликат, запоздавшее сохранение не возвращает отправленный или удалённый черновик. При закрытых ответах сохранённый черновик ответа можно редактировать, но отправить нельзя. После потери доступа к переписке черновик можно удалить; его собственный текст остаётся доступен владельцу через API, история переписки не раскрывается.

### Групповые обсуждения и вложения

«Групповое обсуждение» объединяет от 3 до 200 аккаунтов вместе с автором. Можно выбрать нескольких доступных собеседников; учитель и администратор также могут собрать учеников/родителей по учебным группам. Для переписки семьи с сотрудниками выбирается конкретный ребёнок. Перед отправкой форма показывает число адресатов и предупреждает: участники видят общую историю и имена собеседников. Каждый участник может отвечать. Управляющий может добавлять и исключать участников, закрывать ответы и передавать управление; участник может выйти. Первоначально управляет создатель обсуждения. В разделе «Управление участниками» показаны также неактивные аккаунты, которые можно исключить, чтобы освободить место. Лимит — 200 включённых в состав аккаунтов, в том числе временно потерявших доступ; исключённые его не занимают.

Выход и исключение сразу закрывают доступ к обсуждению и опубликованным вложениям, включая ранее отправленные этим участником; история сохраняется у оставшихся участников. Личные черновики и ещё не отправленные файлы остаются частными материалами владельца. Выход и исключение доступны и при достижении лимита отправки сообщений. Потеря доступа не удаляет историю; исключённый участник автоматически не возвращается при восстановлении учебной связи. Его можно вернуть только явным добавлением управляющим с повторной проверкой прав.

Новые и возвращённые участники получают доступ **ко всей истории и опубликованным файлам**. Перед добавлением нужно выбрать аккаунты и подтвердить эту передачу в форме; API также требует подтверждение. Поиск показывает только подходящие активные аккаунты и загружает страницы по 100 кандидатов; добавление повторно проверяет учебные связи. Изменение состава записывается в историю и создаёт уведомление действующим участникам. Никакого автоматического расширения на новые семьи при изменении классов нет.

Учебная аудитория обсуждения сохраняется при передаче управления. Для группы сотрудников подходят сотрудники с доступом к пространству. Для обсуждения конкретного ребёнка — его действующие представители/ученик, учителя, ведущие его занятия, и администратор. Другого ребёнка того же класса добавить нельзя. Для обсуждения учебных групп семья должна иметь актуальную и зафиксированную при включении связь с учеником в выбранных группах; сотрудником-участником или управляющим может быть администратор либо учитель, ведущий все выбранные группы. Если новый управляющий утратил необходимую связь или отключён, обсуждение становится недоступным; независимое административное восстановление управления пока не реализовано.

Передать управление можно действующему участнику с подходящими правами. Сначала добавьте его в группу, затем выберите в поле «Новый управляющий» и подтвердите действие. Прежний управляющий остаётся обычным участником, может выйти или быть исключён; отключение его аккаунта после передачи не закрывает группу. Авторство обсуждения и прежних сообщений не переписывается. Добавление и передача учитывают лимит отправок; оба действия проверяют версию и обрабатывают повтор запроса без дублей. Ошибка уведомления откатывает действие целиком.

В личном диалоге, групповом обсуждении и объявлении можно отправить до 5 файлов по 10 МиБ, в том числе без текста. Поддерживаются PDF, PNG, JPG, TXT, DOCX, XLSX и PPTX. До отправки файл доступен только загрузившему его аккаунту; после отправки — текущим участникам. Опубликованные файлы нельзя заменить или удалить отдельно от истории. Отзыв объявления закрывает скачивание его получателям. Выдача выполняется как скачивание, без публичных ссылок и кэширования ответа.

При потере ответа загрузки нажмите «Найти мои загрузки» в той же форме и отметьте нужные файлы. Сохраните черновик, чтобы продолжить с вложениями после закрытия вкладки. Выбранные файлы сохранённого черновика защищены от суточной очистки и входят в полную резервную копию. Для удаления такого файла сначала снимите его выбор и сохраните черновик. Неотправленные файлы без ссылки из сохранённого черновика старше суток постепенно очищаются при следующих загрузках; удаление черновика также снимает эту защиту. Сервер проверяет расширение и начальную сигнатуру, но антивирусной проверки пока нет.

Лимит файлов сообщений — 250 МиБ на аккаунт в пространстве за скользящее окно 30 дней (неотправленные файлы, в том числе сохранённые в черновиках, считаются при любом возрасте, отправленные — 30 дней после загрузки; сами отправленные файлы не удаляются и остаются доступными), до 50 неотправленных файлов и 2 незавершённых загрузок аккаунта. Загрузка ограничена 90 секундами. Сообщения и домашние работы совместно используют места загрузки в одном процессе API (16, очередь до 15 секунд) и общий предел `ATLAS_UPLOAD_TOTAL_MB` (по умолчанию 64 ГиБ); у сообщений свой бюджет раздела `ATLAS_UPLOAD_MESSAGES_MB` (8 ГиБ). Место резервируется до получения тела запроса. При занятом сервере ответ 429 с `Retry-After`, и форма сама повторяет загрузку. Файлы сообщений находятся рядом с БД в каталоге `<имя базы>.files/messages`. Полная резервная копия включает БД, файлы сообщений и домашних работ, проверяет размеры/хеши и исключает незавершённые загрузки. Для нескольких процессов API или серверов потребуется общее управление загрузками и хранилищем.

## Отсутствия и объяснительные

Родитель и администратор открывают «Отсутствия и объяснительные» в учебном журнале,
ответственный учитель или сотрудник — в разделе «Работа с классами». Родитель выбирает
ребёнка, первый/последний день и время, указывает причину и при необходимости
прикладывает до пяти файлов по 10 МиБ. «Показать уроки в периоде» использует
текущее фактическое расписание, включая смешанные группы и отмены по классам.
Период непрерывный, максимум 31 день внутри учебного года; время Asia/Qyzylorda.
В форме даты по умолчанию — сегодня по времени школы (в пределах учебного года).
Учитываются полностью вошедшие в период уроки, в том числе созданные позднее.
После переноса урока применяется дата сохранённой редакции журнала: для нового
времени учителю нужно синхронизировать и опубликовать запись.

Администратор назначает ответственных в разделе «Пользователи и доступ» →
«Права работы с классами». Классный руководитель, указанный в карточке класса,
рассматривает объяснительные своего класса по умолчанию, без строки в этом
реестре; реестр остаётся для заместителей и для явного снятия полномочия
(подробнее в CLASS_STAFF.md). Классный руководитель с действующим правом
рассмотрения или администратор может выключить электронные записки класса:
новые заявления и загрузки файлов родителей получают отказ с именем
руководителя, а уже поданные заявления рассматриваются и отзываются как раньше.
Назначение открывает причины и файлы текущих учеников класса, но не оценки
других учителей. Администратор видит все заявления. Родителю доступны только
собственные заявления и только пока действует доступ к ребёнку; другие
представители не видят его причину и документы. Чтение и решения учитываются
в аудите. При переводе ребёнка право рассмотрения следует за текущим классом.

Ответственный принимает или отклоняет заявление с объяснением. Родитель может
отозвать ожидающее заявление; комментарий при отзыве необязателен. Принятое
решение отменяет школа с записью причины.
Принятое заявление переводит «Отсутствует» в «Уважительная причина» в текущем
учёте, личном отчёте и CSV, сохраняя исходную отметку учителя. Отмена возвращает
исходный учёт. Присутствие, опоздание, неотмеченные уроки и оценки не меняются;
черновики не публикуются. Принять объяснительную или отменить принятое решение
нельзя, если её период пересекает закрытый учебный период: сначала администратор
открывает период с причиной. Отклонение и отзыв ожидающего заявления доступны.
Учитель видит отметку о принятой объяснительной без её причины и файлов. Старая редакция журнала показывает исходные значения; историю
решения смотрят отдельно. Для актуального результата обновите журнал.

Для общего решения выберите действие, отметьте до 50 заявлений и заполните
«Объяснение общего решения». Кнопка «Выбрать до 50 загруженных» выбирает только
подходящие записи из уже открытых страниц. Нажмите «Подготовить предпросмотр»,
проверьте учеников, периоды, причины и файлы, затем «Применить ко всем».
Принятие/отказ доступны для ожидающих заявлений, отмена — для принятых.
Если принимаемое или отменяемое заявление затрагивает закрытый учебный период,
общее решение не применяется ни к одному заявлению, а сервер перечисляет
заблокированные.

Предпросмотр привязан к вашей учётной записи и действует 15 минут. Если хотя бы
одно заявление или назначения ответственных изменились, общая операция не сохранит ни одного решения. Обновите список и подготовьте
новый предпросмотр. После ошибки соединения можно повторить применение:
истории и уведомления не продублируются. Каждое заявление получает отдельную
запись истории с общим объяснением; получателю приходит не более одного
уведомления каждого вида на операцию. Лимит — 30 новых предпросмотров в час;
повтор и применение готового решения в него не входят.

Причина и файлы после отправки не редактируются; ошибочное ожидающее заявление
можно отозвать и создать заново. Пересекающиеся ожидающие/принятые заявления
для одного ребёнка не допускаются. Повтор той же отправки не создаёт дубль;
устаревшее решение требует обновления. До десяти заявлений в час на аккаунт.
Списки и история выдаются страницами по 50 записей, внутренние уведомления
сообщают о заявлении/решении без частной причины. Фоновых напоминаний нет.

Текст неотправленной формы не сохраняется. Загрузку с потерянным ответом можно
найти в той же открытой форме. Неотправленные файлы старше суток очищаются при
следующих загрузках; отправленные, включая отклонённые и отозванные заявления,
сохраняются вместе с историей и полной резервной копией. До 250 МиБ на аккаунт
в пространстве, 50 неотправленных файлов и две незавершённые загрузки; общий
предел диска и места загрузки (16 на API) разделяются с сообщениями и домашними
работами, а у объяснительных свой бюджет раздела `ATLAS_UPLOAD_ABSENCES_MB`. Проверяются расширение и сигнатура файла; антивирус ещё не подключён.

## Учебные периоды и закрытие журналов

В разделе «Учебные периоды и закрытие журналов» администратор создаёт четверти,
семестры, учебный год или другие периоды с явными датами. Периоды могут
пересекаться. Перед закрытием нажмите «Проверить перед закрытием»: будут показаны
неполные уроки, отсутствующие публикации и более новые черновики. Незавершённый
период закрыть нельзя; закрытие с пробелами требует явного подтверждения и причины.

Закрытие сохраняет отдельный архив опубликованных тем, отметок и оценок. Черновики
не публикуются автоматически. Изменение, публикация и отзыв журналов блокируются
для всех, включая администратора. Перенос урока не обходит закрытие. Для исправлений
администратор открывает период с причиной, исправляет/публикует нужные журналы и
закрывает его снова. Прежний архив остаётся доступным. Если периоды пересекаются,
нужно открыть каждый закрытый период, затрагивающий урок. После первого закрытия
границы и название периода неизменны.

Проверка перед закрытием теряет силу при изменении журналов дней периода, доступа
или самого периода. Сохранение расписания её не отменяет, если пересчитанные
итоги периода остались прежними; иначе проверьте период ещё раз.

В «Архивах закрытия» доступны уроки страницами, просмотр публикации и её CSV.
Учитель видит публикации назначенных ему преподавателей, администратор — школу.
Причины административных решений видит только администратор. Архив хранит исходные
отметки учителя; объяснительные по-прежнему меняют текущую сводку отдельно.
Решения «принять» и «отменить решение» по объяснительной, затрагивающей закрытый
период, блокируются до его открытия.
Это ещё не выставление итоговых оценок или табель. Учебные периоды журнала не
изменяют чередование недель в расписании.

## Контроль заполнения журналов

В журнале также есть «Контроль заполнения журналов». Выберите период текущего
учебного года, свои уроки или доступные классы, при необходимости учителя,
предмет и состояние. Проверка учитывает отмены/переносы/замены, показывает
неопубликованные и неполные уроки, неотмеченных учеников и старые публикации,
которые не соответствуют текущему расписанию. Свой урок можно открыть для
исправления; после публикации выполните проверку снова. CSV включает все страницы.
Страницы и CSV одной проверки выдаются из сохранённого среза до 10 минут, поэтому
сохранения в других журналах и расписании не прерывают просмотр длинного отчёта;
после этого изменение журналов выбранных дней и учеников, расписания или доступа
требует новой проверки.

Урок проверяется после его окончания по времени школы. «Заполнен» означает
опубликованную тему и отметку каждого известного ученика при подтверждённом
составе; неизвестную численность класса нужно уточнить в основных данных.
Проверка прошлых дат использует текущий план: истории составов и расписания
по учебным периодам пока нет. Напоминания автоматически не отправляются.

## Сводная посещаемость

Администратор открывает «Сводная посещаемость» в учебном журнале, ответственный
учитель или сотрудник — в разделе «Работа с классами». Задайте период до 366 дней,
класс, ученика или предмет и нажмите «Показать сводку». По умолчанию показан
текущий учебный период или месяц по времени школы. Администратор видит всю
школу, ответственный, назначенный в «Пользователи и доступ» → «Права работы с
классами», и классный руководитель класса (пока полномочие не снято в реестре) —
свои классы.
Переключатели показывают итоги по ученикам, классам и предметам. «Уроки ученика»
открывает конкретные даты, предметы и отметки; список можно отфильтровать по виду
отметки. Оценки и частные причины отсутствия в этот раздел не передаются.

Считаются только опубликованные записи. «Не отмечено» не включает уроки без
опубликованного журнала; их число пока не рассчитывается. Ученики без записей
выделяются отдельно. Состав классов текущий, включая неактивных учеников;
исторический состав класса на конкретную дату пока не восстанавливается.
Администратор может выбрать группу записей учеников «Вне текущего состава».

Принятая объяснительная учитывается как уважительная причина только для исходного
отсутствия на полностью покрытом уроке; отмена решения обратима. В подробностях
видна исходная отметка. Отчёт использует дату/время опубликованной редакции:
перенос урока нужно синхронизировать и опубликовать в журнале, ненужную публикацию
отозвать. Черновики и непубликованные правки в сводку не входят.

«Скачать сводку CSV» выгружает все строки текущего вида, включая следующие
страницы. Есть отдельная выгрузка уроков ученика (до 10 000 строк). Страницы и файл
одной сводки берутся из сохранённого среза до 10 минут и не смешивают разные
состояния; сохранение расписания или публикации других классов их не прерывает.
После этого изменение данных выбранных учеников и периода или доступа потребует
заново показать сводку («Показать сводку»). Список уроков ученика читается заново.
Старые выгрузки на устройстве автоматически не обновляются.

## Реестр семей

В «Пользователи и доступ → Семьи и доступ к детям» администратор ищет пары
родитель–ученик, назначает ребёнка существующему аккаунту родителя, указывает
отношение, проверку школой, закрытое основание, даты и причину изменения.
История сохраняет предыдущие значения и автора. Основания, причины и история
доступны только администраторам; их чтение записывается в аудит.

Родитель открывает «Мои дети и доступ»: только собственные дети и состояние
разрешений, включая будущие, истёкшие и отозванные связи. Данные другого
представителя не раскрываются. Аккаунт может оставаться без действующих детей.
Отзыв одного назначения не затрагивает других детей и представителей.

Даты включают последний указанный день по времени Asia/Qyzylorda. Сроки
проверяются на каждом запросе расписания, журнала, домашних работ, файлов,
сообщений и выбора курсов. Повторный вход и перезапуск не нужны; уже показанные
данные исчезают при следующем обновлении страницы, а не удаляются из памяти
пользователя. Само наступление даты пока не создаёт фоновое уведомление.
Изменение через реестр создаёт внутреннее уведомление действующему родителю.

Старые назначения продолжают работать с отметкой «требует уточнения»; чтение
реестра не меняет их. Первое изменение сохраняет прежнее назначение в истории.
Приглашения создают непроверенные связи. Отозванную связь можно восстановить
только явно через реестр: старый код и обычная правка аккаунта не снимают отзыв.
При одновременных изменениях нужно обновить данные и повторить решение.

Отметка проверки означает работу сотрудника школы, а не автоматическую проверку
документа. Выдача ребёнка реализована отдельно в [HANDOVER.md](HANDOVER.md),
формы согласий — в модуле форм. Общие разрешения по действиям и проверка контактов
остаются в плане. Частные сведения входят в полную резервную копию.

## Жалобы и восстановление обсуждений

Участник может пожаловаться на конкретное чужое сообщение. Форма требует причины и явного согласия передать администраторам сообщение, его вложения, тему и имя заявителя. Другие сообщения и список участников не передаются. До пяти жалоб в час; повтор на тот же пост отклоняется. Заявитель видит свои обращения и историю решений в разделе сообщений, даже после утраты членства, пока у аккаунта остаётся доступ к этому пространству.

Администратор открывает «Жалобы и восстановление групп», изучает переданные материалы и объясняет решение: отклонить, скрыть сообщение с файлами или восстановить. Жалобу на сообщение администратора рассматривает другой администратор. Текст скрытого сообщения исключается из поиска и истории, обычное скачивание его файлов запрещается. Исходные материалы сохраняются для рассмотрения и полной резервной копии. Просмотры материалов, скачивания и решения пишутся в аудит; версии защищают от одновременного изменения одного сообщения по разным жалобам. Отзыв объявления и потеря участником доступа не уничтожают уже переданные доказательства. Статус жалобы отражает решение по ней; отдельное поле показывает текущее состояние сообщения с учётом остальных жалоб.

Если управляющий группой отключён, исключён либо потерял подходящие учебные связи, администратор может выбрать нового из существующих действующих участников. В список не входят исключённые, неактивные аккаунты и участники без подходящего назначения. При отсутствии кандидата нужно сначала исправить реальные аккаунты/учебные назначения. Восстановление не добавляет администратора в группу и не открывает ему историю; причина и имя нового управляющего появляются у участников. Действующий управляющий передаёт управление самостоятельно.

Материалы жалоб пока хранятся без автоматического удаления; отдельные роли модераторов, апелляции и политика хранения ещё не реализованы. Механизм фоновой доставки Web Push добавлен отдельно; его включение и ограничения — [PUSH_NOTIFICATIONS.md](PUSH_NOTIFICATIONS.md). Изменения видны после обновления сообщений; уже просмотренный текст или скачанный файл нельзя отозвать с устройства получателя.
