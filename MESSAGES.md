# Сообщения: каналы, адресаты, входящие и лента

Этот файл описывает вторую волну раздела «Сообщения» и «Главной» страницы. Общее
описание диалогов, обсуждений, вложений, черновиков и жалоб — в разделе
«Сообщения и объявления» файла README.md.

## Каналы сообщений

Канал — одно направление: кто может **первым** написать кому. Состав каналов
хранится отдельно для каждого пространства; без сохранённой настройки действуют
значения по умолчанию, которые повторяют правила до появления матрицы. Все каналы,
которые расширяют круг адресатов, по умолчанию **выключены**.

Администратор открывает «Сообщения → Каналы сообщений», отмечает нужные каналы,
указывает причину и сохраняет. Настройка версионируется: параллельное изменение даёт 409,
каждая редакция, автор и причина записываются в историю и журнал действий.
Читать и менять матрицу может только администратор. Администратор как отправитель
в матрице не нуждается: он пишет всем, с кем связан.

| Канал | По умолчанию | Что разрешает |
| --- | --- | --- |
| Ученик → учителям, которые его учат | включён | `student_teachers` |
| Ученик → администрации | включён | `student_admin` |
| Ученик → классному руководителю | выключен | `student_class_teacher`: классный руководитель по записи класса |
| Ученик → любому учителю школы | выключен | `student_any_teacher` |
| Ученик → одноклассникам | выключен | `student_classmates`: ученики того же класса |
| Родитель → учителям ребёнка | включён | `parent_teachers` |
| Родитель → администрации | включён | `parent_admin` |
| Родитель → классному руководителю | выключен | `parent_class_teacher` |
| Родитель → любому учителю школы | выключен | `parent_any_teacher` |
| Родитель → родителям класса | выключен | `parent_class_parents`: имена родителей других детей класса появляются в списке собеседников только при включении |
| Учитель → ученикам своих групп | включён | `teacher_students` |
| Учитель → родителям своих учеников | включён | `teacher_parents` |
| Классный руководитель → ученикам и родителям класса | выключен | `class_teacher_families`: расширяет доступ к ученикам классов, где учитель — классный руководитель, даже если он их не ведёт |
| Учитель объявляет учителям, классным руководителям и сотрудникам | выключен | `teacher_colleagues_all` |
| Учитель объявляет всей школе | выключен | `teacher_school` |
| Сотрудники → друг другу | включён | `staff_staff` |
| Автор объявления может открыть ответы всем получателям | выключен | `feed_public_replies` |

**Классный руководитель** определяется записью класса (`classTeacherId`) при каждом
запросе и нигде не копируется. При смене классного руководителя прежний диалог
становится только для чтения, если между людьми нет другой связи.

### Направления, ответы и история

* Начать диалог можно, если канал открыт **от отправителя**. Продолжить (ответить)
  может участник, если канал открыт от него к кому-то из участников либо от автора
  диалога к нему. Пример: выключен «родитель → учителям», включён «учитель →
  родителям». Родитель не начинает диалог, но отвечает в диалоге, начатом учителем;
  в диалоге, начатом родителем, отвечает только учитель.
* Канал, закрытый **в обе стороны**, превращает существующий диалог в историю только
  для чтения; данные не удаляются, при повторном включении диалог оживает. Диалоги,
  созданные до обновления 0.6a и ни разу не открытые, пока скрыты, пока канал закрыт.
* Администратор остаётся в диалоге, пока он связан с участником, независимо от матрицы.
* Группа семьи с родителями класса остаётся живой, пока канал открыт; при выключении
  канала для этих родителей она становится историей.
* Ответ сотрудника, который доходит до семьи (в беседе есть родитель или ученик),
  требует открытого канала именно к кому-то из семьи. Другой сотрудник в той же беседе
  канал не заменяет: если закрыты «учитель → родителям» и «учитель → ученикам», учителя
  не пишут в существующую группу семьи, сколько бы коллег в ней ни было, а добавление
  коллеги канал не возвращает. Беседа только сотрудников зависит от «сотрудник ↔
  сотрудник».
* Семья одного ребёнка (родитель и ученик, два родителя) отвечает друг другу в беседе о
  нём всегда, даже когда учителя потеряли связь с ребёнком, а каналы «родителям класса» и
  «одноклассникам» выключены: так же, как управляющий вправе добавить другую семью этого
  ребёнка. Семья другого ребёнка этим правилом не пользуется.
* «Добавить участника» предлагает только тех, кого управляющий вправе добавить сейчас
  (сервер проверяет то же самое): канал к человеку открыт, а родитель, ведущий группу своего
  ребёнка, видит семьи того же класса, пока открыт канал «родителям класса». Другого
  родителя того же ребёнка он добавляет всегда.
* Учитель, ведущий беседу о ребёнке, добавляет только коллег, которые сами связаны с этим
  ребёнком. Учителя, не ведущего ребёнка, в беседу приводит только семья: родитель при
  открытом «родитель → любому учителю», ученик при открытом «ученик → любому учителю».
  Такой учитель остаётся в беседе, пока открыт канал каждой роли семьи, участвующей в
  ней (родитель, ученик); если один из каналов закрыли, он читает историю, но не пишет.

### Что рекомендуем решить при запуске

Школа уже привыкла к EduPage, где все каналы включены. После обновления выберите,
какие каналы выключенные по умолчанию включить: «классному руководителю», «родителям
класса», «любому учителю». Пока администратор их не включит, поведение остаётся
прежним. «Мои классы» у классного руководителя, не ведущего свой класс, появляется
только после включения `class_teacher_families`.

### Роль «Сотрудник»

Учётная запись роли `staff` получает вкладку «Сообщения» рядом с «Работой с классами».
Она пишет только сотрудникам (как редактор и наблюдатель), не видит семьи и учеников,
не публикует объявления, получает объявления для роли «Сотрудник». Запись должна иметь
доступ к пространству.

## Адресаты объявления

Объявление выбирает аудиторию списком «Кому». Сервер каждый раз вычисляет состав заново
по текущим данным: учебным группам, классам, назначениям, активности аккаунтов и матрице.
Предварительная проверка только подсказывает; при отправке состав определяется снова.
Отправка в аудиторию «выбранные группы» старого вида продолжает работать.

| Аудитория | Кто может | Состав |
| --- | --- | --- |
| Вся школа | администратор; учитель при `teacher_school` | роли по выбору; учитель: ученики, родители и учителя |
| Все учителя | администратор; учитель при `teacher_colleagues_all` | активные учителя |
| Классные руководители | то же | учителя, являющиеся классными руководителями |
| Сотрудники | то же | роли «Сотрудник», «Составитель», «Наблюдатель» |
| Мои классы | учитель | ученики/родители классов, в которых учитель ведёт целую группу (и классы, которые он ведёт как классный руководитель, при `class_teacher_families`); роли «ученики», «родители» |
| Мои курсы и группы | учитель | ученики/родители ваших групп по нагрузке или выбранных групп; замена на один урок состав не меняет |
| Сохранённая группа | администратор и учитель | личный список аккаунтов, проверяемый при каждой отправке |

Учитель пишет ученикам и родителям только при включённых `teacher_students` и
`teacher_parents` (в обоих способах отбора). Неактивный ученик и его родитель не
попадают в список; переведённый в другой класс получатель определяется по актуальному
классу.

Предел одного объявления — 5000 получателей. «Проверить получателей» показывает число,
роли, до 20 имён с пометкой «и ещё N», сколько человек из сохранённой группы недоступны
сейчас, и предел; при превышении отправка отключена, а сервер отклоняет её с 422.
Группа в обсуждении по-прежнему вмещает до 200 аккаунтов. Объявление требует темы.
Рассылка вставляет участников и уведомления в одну транзакцию записи, на время которой
она занимает писателя базы; отправка 2200 родителям на синтетической базе заняла около 0,4 с (388,5 и 439,8 мс в двух прогонах, см. PERFORMANCE.md), для 5000 получателей время не измерялось.

### Сохранённые группы

Личные списки аккаунтов: до 20 групп, до 500 человек, название до 120 знаков. Группа
видна только владельцу (чужая даёт 404), хранит только идентификаторы и не расширяет
доступ: недоступные сейчас (связь потеряна, канал выключен, аккаунт отключён)
пропускаются при отправке и подсчитываются в проверке, но не удаляются автоматически.
Сохранение проверяет версию и право писать каждому человеку; при изменении недоступные
члены убираются.

## Входящие

Строка входящих показывает отправителя, дату последнего прочитанного вами сообщения,
имя ребёнка (семье — только имена своих детей), начало текста (до 140 знаков), тему,
если она есть, и пометку «Вложение». Скрытое администратором сообщение заменяется
фразой о скрытии. Бывший участник видит последнее сообщение, написанное до потери связи.

Тема диалога и обсуждения необязательна; у объявления обязательна. Заголовок
«Входящие · N непрочитанных» и счётчик на вкладке «Сообщения» считают переписки,
которые аккаунт вправе читать (до 100 просмотренных; «99+» или «N+», если их больше).
Список и счётчик обновляются раз в минуту (60 с) без действий пользователя, пока вкладка
открыта; счётчик читается отдельным запросом `GET /api/messages/unread` через соединение
только для чтения. Во время написания сообщения или чтения переписки список не
перезаписывается. Нагрузка опроса на школьный сервер не измерялась.

## Лента на «Главной»

Первая вкладка личного кабинета (учитель, ученик, родитель) — «Главная»: объявления,
отправленные аккаунту, новые сверху, с вложениями, подтверждением ознакомления,
«Нравится» и ответами. Открытие ленты помечает показанные объявления прочитанными.
Ленту видят текущие получатели и те, кто получал объявление ранее (только чтение).

* **Ответы** автор включает при создании: «Без ответов», «Только автору» или «Всем
  получателям» (нужен канал `feed_public_replies`; имена и ответы станут видны всем
  получателям — форма предупреждает об этом). Если канал выключили позже, режим «всем»
  ведёт себя как «только автору».
* Видимость ответа фиксируется при отправке. Ответ, написанный, пока канал был выключен
  (то есть как «только автору»), остаётся личным и после повторного включения канала.
  Ответы, написанные в открытом режиме, скрываются от других получателей, пока канал
  выключен, и возвращаются при его включении.
* Ответ — текст до 2000 знаков под корневым сообщением. Он не создаёт новое непрочитанное
  сообщение, не сбрасывает подтверждение ознакомления и не меняет границу истории.
  Автору приходит уведомление «Ответ на ваше объявление» без текста.
* В режиме «только автору» получатель видит свои ответы, автор — все; автор отвечает
  отправителю личным диалогом. В режиме «всем» получатель видит все ответы; бывший
  получатель — только свои.
* Отозванное объявление пропадает у получателей; у автора ответы и «нравится» закрыты (409).
* На ответы действуют лимит 30 сообщений за 5 минут и жалобы. Жалоба на ответ, который
  жалобщик не вправе читать, даёт 404. Скрытие ответа не сбрасывает подтверждения.
* «Нравится» ставится только корневому объявлению; повтор не удваивает отметку, имена
  не показываются никому, уведомлений нет. У бывшего получателя отметка не ставится.

Администратор и составитель работают в разделе «Сообщения»: там под объявлением
видны ответы и отметки.

Уведомления о сообщениях называют автора и тему беседы (у личной беседы без темы —
«Сообщение от …») и ребёнка, если он уже виден получателю; текст сообщений, причины
жалоб и заметки решений в них не входят. Ответы одной беседы оставляют одну
непрочитанную запись; отзыв объявления стирает заголовки у всех получателей.
«Открыть» ведёт к беседе и заново проверяет доступ, в том числе сохранённую историю.
Запрос открыть беседу одноразовый: повторное «Открыть» у той же записи снова
показывает беседу, а смена пространства после этого её не повторяет.

## Вложения

Разрешены PDF, PNG, JPG, TXT, DOCX, XLSX, PPTX и, только в сообщениях, HEIC, HEIF, DOC,
XLS. Сервер проверяет подпись содержимого: для HEIC/HEIF — контейнер ISO (`ftyp` и
известный бренд), для DOC/XLS — подпись OLE2; переименованный файл с другим содержимым
отклоняется. Остальные модули (домашние работы и др.) принимают прежний набор типов.

Фото JPG, PNG, HEIC и HEIF показываются в переписке и ленте над ссылкой на скачивание.
Сервер отдаёт файл как изображение (`inline`) только после проверки подписи и только
для этих типов; для остальных остаётся скачивание. Заголовки `nosniff`, `no-store` и
песочница CSP сохраняются. HEIC показывается там, где браузер умеет его декодировать
(Safari); в других браузерах остаётся ссылка. Серверного преобразования нет. DOC и XLS
могут содержать макросы: они доставляются только как скачивание в песочнице.

## Что не сделано

* Проверка текста ИИ — отдельная работа без поставщика.
* Срезы ленты (экзамены, фото, записки на подтверждение, избранное), оценки на главной.
* Вложения и «нравится» у самих ответов.
* История ответов бывшего получателя (он видит свои).
* Блокировка пользователя со скрытием сообщений.
* Приёмка Web Push на Android и iPhone — требует реальных устройств.
* Интерфейс не проверялся в браузере вообще: ни на 375 px, ни на искусственных данных.
  Он покрыт только сборкой (`tsc`, `npm run build`) и модульными тестами TypeScript;
  вид списка, ленты, фото, формы создания, матрицы каналов и вкладки сотрудника на узком
  экране предстоит проверить на демо-пространстве с временной БД.
