# Контроль заполнения журналов

«Контроль заполнения журналов» сопоставляет текущее расписание с опубликованными
журналами, показывает сводку по классам с датой последней записи и датой, с
которой журнал не заполнен, предупреждает об уроках, которые некому заполнить
(у учителя нет учётной записи), и по желанию школы напоминает учителям о
незаполненных уроках. Алгоритм проверки периода, токены, страницы, кэш и CSV
описаны в [FEATURES.md](FEATURES.md), раздел «Контроль заполнения журналов»; здесь
— роли, сводка по классам и напоминания.

Это собственное решение «Атласа» по описанию EduPage из
[EDUPAGE_SPEC.md](EDUPAGE_SPEC.md) (строка 4 и раздел «Классный журнал
(администрация)»). Настройки EduPage не просматривались, поэтому полного аналога
не заявляется.

## Роли

| Кто | Что видит и делает |
|---|---|
| Администратор | Всю школу: проверку, сводку по классам, список учителей без учётной записи, настройки напоминаний и их последние запуски |
| Классный руководитель или заместитель с правом «Контроль заполнения журналов» ([CLASS_STAFF.md](CLASS_STAFF.md)) | Проверку и сводку по своим классам. Список учителей без учётной записи не показывается: наличие учётной записи коллеги — сведения об администрировании доступа |
| Учитель | Проверку собственных уроков («Преподаю»); сводку — только если он ещё и классный руководитель или заместитель. Получает напоминания о своих незаполненных уроках |
| Сотрудник (`staff`) | Только классы, где ему назначено право «Контроль заполнения журналов»; напоминаний не получает |
| Ученик, родитель, наблюдатель | Нет доступа: 403 |

Локальный пользователь (учётные записи ещё не включены) действует как
администратор. Учётных записей учителей при этом нет, поэтому напоминания никому
не доходят, а каждый урок записывается как «пропущенный» (`skipped`).

## Что значит «не заполнено»

Урок учитывается, когда он уже закончился по времени школы (Asia/Qyzylorda).
«Не заполнено» — это один из состояний:

- журнал не создан;
- есть только черновик, публикации нет;
- публикация устарела (расписание или состав изменились после публикации);
- публикация неполна из-за темы или отметок: нет темы, есть ученики без записи
  или без отметки.

Неполной «только из-за неизвестной численности класса» публикация, которая иначе
заполнена, **не** считается незаполненной: это вопрос основных данных школы
(администратор уточняет численность), а не работа учителя. Такие уроки
показываются в сводке отдельной строкой «Численность класса не подтверждена», а
напоминание по ним не отправляется. Это единственное определение
(`journal_coverage.actionable`), общее для сводки и напоминаний.

Не напоминаются и не входят в «не заполнено»: отменённые уроки, занятия
сотрудников, будущие и ещё не закончившиеся уроки, публикации вне расписания
(«вне текущего состава»). Опубликованный прошедший урок проверяется по своему
опубликованному составу, поэтому поздно добавленный ученик не делает давно
заполненный урок незаполненным.

## Сводка по классам

Кнопка «Сводка по классам» в форме проверки (режим «Классы») строит по одной
карточке на класс за выбранный период:

- классный руководитель;
- «Последняя запись» — дата последнего урока класса, у которого есть публикация;
- «Не заполнено с» — дата самого раннего незаполненного урока;
- «Не заполнено уроков: N из M» — M — ожидаемые (закончившиеся) уроки;
- «Некому заполнить (у учителя нет учётной записи)» — незаполненные уроки, у
  которых ни один учитель не привязан к учётной записи;
- «Численность класса не подтверждена» — закончившиеся уроки без подтверждённого
  состава;
- кнопка «Уроки класса» открывает обычный отчёт, отфильтрованный по классу и
  состоянию «Требует внимания».

Межклассная группа учитывается в каждом классе, который она охватывает (как в
журнале EduPage). Класс без уроков за период остаётся в списке с нулями. Архивные
публикации без текущего класса ни за каким классом не числятся.

Сводка строится из того же сохранённого среза и тем же токеном, что и отчёт
(`POST /api/journal/coverage/classes`, режим «Классы»): повторный расчёт для
одинаковых фильтров не нужен. Ответ не содержит ни имён учеников, ни их
идентификаторов. Дрилл-даун — обычный `POST /report` с `classId` и без токена:
токен сводки к нему не подходит (данные выбранного класса отличаются), поэтому
интерфейс передаёт только зафиксированный момент проверки. Чтение записывается
в аудит (`journal.coverage_classes_read`).

### Учителя без учётной записи

Только для администратора: список «Уроки без учётной записи учителя» — учитель,
число незаполненных уроков, «с» какой даты и классы. Привязка читается заново при
каждом запросе, поэтому после привязки учётной записи предупреждение исчезает
сразу. Уроки без назначенного учителя собраны в группу «Учитель не назначен».
Привязывать учётные записи нужно в разделе доступа.

## Напоминания учителям

Настройки доступны администратору (`GET`/`PUT /api/journal/coverage/reminders`,
вкладка «Напоминания учителям» в контроле заполнения). Они хранятся отдельно для
каждого пространства («demo» и «school»), версионируются (устаревшая версия —
409), а каждое изменение записывается в историю с причиной и в аудит
(`journal.coverage_reminders_saved`).

| Параметр | По умолчанию | Смысл |
|---|---|---|
| Напоминать | выключено | Включает фоновые напоминания |
| Через сколько учебных дней | 2 | От 1 до 10 учебных дней после урока |
| Во сколько | 16:00 | Школьное время; раньше этого часа не отправляется |
| Напоминание по каждому уроку | включено | Одно уведомление на учителя за запуск |
| Недельная сводка | выключено | Раз в неделю в выбранный день |
| День сводки | пятница | Понедельник… воскресенье |

Напоминания выключены по умолчанию намеренно: учителя пока работают в EduPage, и
включение при запуске обрушило бы на них накопленную очередь. Администратор
включает их сам.

### Учебные дни

«Через N учебных дней» считает с дня, следующего за уроком (сам день урока не
входит). Не считаются: выходные (кроме дня, назначенного «днём в расписании»),
дни вне учебного года и дни, закрытые для всей школы — каникулы, праздник
(`holiday`, `winter`) или отмена (`cancel`), охватывающие все классы. Закрытие
только части классов день учебным оставляет. Примеры при N = 2: урок в понедельник
напоминается в среду, в пятницу — во вторник, в пятницу перед праздничным
понедельником — в среду.

### Время и однократность

- Фоновый процесс проверяет школу раз в минуту. Начиная с заданного часа, в
  учебный день, он один раз пересчитывает контроль заполнения от имени системы по
  урокам, срок напоминания которых наступил, и рассылает уведомления. Запуск
  записывается как выполненный на день.
- Если день не учебный, запуск записывается как «не учебный день»; уроки ждут
  ближайшего учебного дня. Сервер, который был выключен несколько дней, догоняет
  уроки, срок которых наступил не раньше 7 дней назад (`GRACE_DAYS`); более
  старые остаются только в недельной сводке.
- На один урок и учителя приходит **одно** напоминание за всё время: строка в
  `journal_coverage_reminders` с ключом (пространство, урок, учитель). Повтор не
  отправляется после перезапуска и после смены «N дней». Уведомления, строки и отметка
  запуска пишутся в одной транзакции (`BEGIN IMMEDIATE`) с проверкой ревизии
  школы, версии настроек и версии каждого урока: урок, который учитель
  опубликовал во время расчёта, в напоминание не попадает.
- Один учитель — одно уведомление за запуск со счётчиком уроков и самым ранним
  уроком (дата, класс, предмет). Текст не содержит имён учеников и оценок.
  Фоновые (push) уведомления несут постоянный текст без подробностей.

### Кому

Урок напоминается учителю, который ведёт его сейчас: замена на день заменяет и
получателя. Если у урока два учителя, получают оба. Напоминание не отправляется
по отменённым урокам, по урокам в закрытых учебных периодах (урок закрыт, если
закрыт его день или день, откуда он перенесён) и по урокам до даты включения
(`since`). Учитель без учётной записи получает строку «пропущено» (`skipped`) и
больше не рассматривается по этому уроку; он виден в сводке по классам.

### Дата включения

При каждом включении (переход из «выкл.» в «вкл.») сервер записывает `since` —
сегодняшний школьный день. Уроки раньше этой даты не напоминаются; выключение и
повторное включение сдвигают `since` на день повторного включения, так что уроки
выключенного промежутка не напоминаются никогда.

### Недельная сводка

Раз в выбранный день недели после заданного часа, даже если день не учебный,
каждый учитель получает одно уведомление «За 4 недели не заполнено уроков: N,
самый ранний — дата». В сводку попадают все незаполненные уроки последних 28 дней,
срок напоминания которых наступил, в том числе те, о которых уже напоминали:
сводка повторяется, пока урок не заполнен. Прежнее непрочитанное уведомление
сводки заменяется новым. Сводка не пишет строк в `journal_coverage_reminders`;
число учителей без учётной записи записывается в сведения запуска. Можно включить
только сводку, без напоминаний по урокам.

### Что хранится

Четыре таблицы создаются при первом обращении (`CREATE TABLE IF NOT EXISTS`, без
удаления и без переноса данных; в существующей базе напоминания остаются
выключенными): `journal_coverage_settings`, `journal_coverage_settings_history`,
`journal_coverage_reminders`, `journal_coverage_runs`. Строки напоминаний и
запусков старше 180 дней (`KEEP_DAYS`) удаляются. Последние запуски видны
администратору в настройках.

### Единственный API-процесс

Фоновый процесс (поток `atlas-coverage-reminders`) запускается вместе с
приложением и останавливается при остановке. Отправка отмечается в базе в одной
транзакции с уведомлением, но запуск рассчитан на один процесс: несколько
API-процессов не поддерживаются проектом в целом, см.
[DEPLOYMENT.md](DEPLOYMENT.md).

## Ограничения

- Информационный праздник (эффект «заметка») останавливает отсчёт учебных дней,
  но проверка по-прежнему ждёт на этот день уроки. Пока школа не отметит день как
  закрытие с отменой, учитель может получить напоминание по уроку, которого не
  было.
- Если срок напоминания приходится после конца учебного года, напоминания нет.
- Замена, внесённая после напоминания, второго напоминания не вызывает (одно на
  урок); недельная сводка это покрывает. Привязка учётной записи к ранее
  «пропущенному» учителю тоже не создаёт запоздавшего напоминания.
- Учитель без учётной записи пропускается навсегда по этому уроку.
- Уведомление не содержит подробностей, push-уведомление несёт только
  постоянный текст.
- Календарь учебных дней берётся из текущего расписания (события, дни в
  расписании и границы года не версионируются).
- Часовой пояс школы задан в коде (Asia/Qyzylorda).
- Сводка по классам не показывает ежедневное подтверждение посещаемости, график,
  печать и численность учеников по классам: только счётчики уроков.
- Ежедневный расчёт охватывает не более 60 дней и всю школу; на настоящей школе
  он отдельно не измерялся (см. [PERFORMANCE.md](PERFORMANCE.md)).
