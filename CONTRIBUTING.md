# Совместная работа над Атласом

Репозиторий: https://github.com/gagafik/atlas. Код общий; базы разработки у каждого свои.

## Первый запуск

Нужны Git, Python 3.12 и Node.js 22. Клонируйте репозиторий:

```sh
git clone https://github.com/gagafik/atlas.git
cd atlas
```

На Windows выполните `./start.ps1` в PowerShell. Скрипт создаёт `.venv`, ставит
зафиксированные зависимости и собирает интерфейс. После изменений интерфейса
выполните `npm.cmd ci` и `npm.cmd run build` перед перезапуском.

На Linux/macOS:

```sh
python3.12 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.lock.txt
npm ci
npm run build
python -m uvicorn backend.api:app --host 127.0.0.1 --port 8000
```

Откройте http://127.0.0.1:8000 и переключитесь на демонстрационные данные.
Новый клон не содержит настоящих учеников, аккаунтов или школьного расписания.
Для разработки интерфейса можно отдельно выполнить `npm run dev`: Vite на 5173
перенаправляет API к Python-серверу на 8000. Не открывайте локальный режим без
учётных записей в интернет; серверный запуск описан в `DEPLOYMENT.md`.

## GitHub и Claude коллеги

1. Mondohokan принимает приглашение в репозиторий под своим GitHub-аккаунтом.
2. Для Claude Code: открыть собственный клон репозитория; `CLAUDE.md` подключит

3. Для облачного Claude: подключить собственную интеграцию GitHub и разрешить ей

   разрешение установленному GitHub-приложению — его настраивает владелец аккаунта.
4. Установить gstack в своём окружении, если Claude будет работать с браузером.
   Общие инструкции не устанавливают навыки и инструменты автоматически.

Не передавайте коллеге пароль или токен владельца. Право записи позволяет
создавать ветки, делать PR и работать над кодом. Репозиторий пока находится в
личном аккаунте: для двух равноправных владельцев настроек нужна организация
GitHub с отдельно настроенными ролями; перенос без решения владельца не выполняется.

Доступ к работающей школе выдаётся отдельно через раздел аккаунтов Атласа;
доступ к будущему серверу — отдельным SSH-ключом. Supabase сейчас не подключён.

## Рабочий цикл

```sh
git switch main
git pull --ff-only
git switch -c claude/short-task-name
# Изменения и проверки
python -m pytest -q
npm test
npm run build
python tools/check_repository.py
git add <изменённые-файлы>
git commit -m "Describe the resulting behavior"
git push -u origin claude/short-task-name
```

Откройте PR в `main`, укажите решённую задачу и результаты проверок. Для Codex
используется префикс `codex/`. Согласуйте модули перед одновременной работой.
Не берите настоящее расписание как тестовый пример и не коммитьте `data/`.
Не объединяйте конфликтующие JSON-файлы рабочей базы через Git.

CI проверяет Python, клиент, сборку, исключение закрытых файлов и запуск
Docker-образа с обязательной авторизацией. Статус CI проверяется на конкретном
коммите PR. Публикация на рабочий сервер пока выполняется вручную по инструкции.
